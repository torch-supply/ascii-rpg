# Ember of Dawn — ASCII RPG

A single-player, browser-based ASCII RPG. Next.js (App Router) + TypeScript, **client-only** (no backend; static export to `out/`), rendered with **rot.js** on a canvas, styled with **Tailwind v4**, state in **Zustand**.

## Run

- `npm run dev` — dev server
- `npm run build` — static export
- `npm run test:core` — pure-engine checks (determinism, goals, combat, connectivity, and Phase 2/3 mechanics: status effects, fire/oil, elites, stealth, ranged, altars, cracked-wall demolition, decals, shop selling, the survive siege, class active abilities, run modifiers, par-for-score bonus, a par-reachability floor, flood set-piece (altars stay reachable, doors dam the water), chasm falls (shover knockback into the void), bramble (snag-bleed + fire clears it), spore vents (bounded poison haze), lore props (placed/distinct/reachable), ambient wisps (flee/harmless/disperse), the gallery generator (niche offerings + varied collapsed pit), the dawn/dusk ambient beat (`beatAmbient` warms vs. dims by intensity), and all-placed-items reachability incl. gated hut/vault loot) via `scripts/verify-core.mts`. Tests mechanics in **isolation** (one hand-built scenario per check).
- `npm run test:play` — **autonomous-playthrough / balance harness** (`scripts/verify-playthrough.mts`): a greedy bot (real class kit + the shop consumables a player buys — heals & firebombs — no god-mode) plays every level across many seeds and asserts no invariant violations during real play, navigation/attrition levels are bot-beatable, boss/siege levels are enterable (not instant wipes), and outcomes are deterministic. The bot bump-attacks, auto-heals when low, hurls firebombs at bosses/clusters (kiting to reopen bombing distance), fires an equipped bow, and **flees to open ground on survive levels / when surrounded**, so boss & siege win-rates are a real (if conservative) signal of the intended toolkit, not just pure melee. Prints a per-level difficulty table (win-rate / median turns / median end-HP / median gold-earned / median death-turn) — the win-rate is a conservative **floor** (greedy, non-optimal bot), so a low win% _with_ a low death-turn flags a meat-grinder; use the table to spot over/under-tuned levels. (The final lich stays ~0% — its multi-phase barrage/summon/blink fight is beyond a greedy bot, so that row is "not measurable here," not a balance verdict.)
- `npm run test:store` — **store-level orchestration harness** (`scripts/verify-store.mts`): drives the vanilla Zustand store (`gameStore`) headlessly to assert the LoopDriver's run/screen flow — boot (splash→class→opening narration→play), the anti-skip input-settle guard, level-clear→narration→shop→next-level ordering, shop economy (buy coin/qty caps + sell), death→restart-level vs. last-life→game-over, final-level→victory, the lore-prop interaction flow (step onto → read modal → dismiss → stays read), and the save/resume roundtrip. Installs an in-memory `localStorage` shim (`sound`/`effectBus` self-guard to no-ops under Node).
- `npm run test:all` — runs all three suites in sequence.
- `npm run lint` / `lint:fix` — ESLint (flat config `eslint.config.mjs`: `eslint-config-next` core-web-vitals + typescript, with `eslint-config-prettier` last; React-hooks rules off for the pure `src/game/**` + `scripts/**`). `npm run format` / `format:check` — Prettier (`.prettierrc`, double quotes). A **husky pre-commit hook** (`.husky/pre-commit` → `lint-staged`) runs Prettier `--write` **then** ESLint (no `--fix`, so a lint error fails the commit) on staged files.

**Dev tooling** (gated on `DEV = process.env.NODE_ENV !== "production"`, so it's absent from the static build): the splash shows a **level picker** that jumps into any level with a tier-appropriate loadout (`store.debugJumpTo`), and in play `>` skips to the next level (`debugSkipLevel`).

## Architecture — one-directional data flow

```
KeyboardInput → store.handleCommand → store.submitAction (the turn-based LoopDriver)
   → pure core transitions (resolveTurn) → new GameState
       ├→ React HUD/screens (Zustand selectors)
       └→ rot.js CanvasRenderer (store.subscribe)  +  cosmetic effects via effectBus
```

React and the canvas are **read-only consumers** of state. No timing lives in the core — that keeps a future turn-based→real-time swap contained (replace `submitAction`/`LoopDriver`, add tweening; core/renderer/save untouched).

### Load-bearing rules

1. **Two RNG streams** (`src/game/core/rng.ts`). Map geometry is seeded from the GLOBAL `ROT.RNG` via `seedMapGen(levelSeed(master, index))` — a pure function of seed+index. Gameplay uses a separate cloned `Rng` whose state is persisted in the save. Never let them share.
2. **Canvas is client-only.** `src/app/page.tsx` dynamically imports `GameRoot` with `ssr:false`; `ROT.Display` is created in a `useEffect` and appended to a React-owned div. React never reconciles canvas contents.
3. **Pure core.** `src/game/core/**` has no React/Zustand/DOM imports. `resolveTurn` (`src/game/core/actions/index.ts`) mutates a GameState and returns a `TurnResult` (including cosmetic `events` for the animation layer — animations NEVER touch game state).

## Rendering

Camera-based viewport: the renderer draws a window sized to the host at a fixed cell size (`TARGET_ROWS`) and scrolls to keep the player in view (edge-clamped) — the map may exceed the viewport. Fog-of-war with **dynamic colored lighting** (`src/render/lighting.ts` → `computeLightMap`, via `ROT.Lighting`): multi-source light spreads through the FOV and bounces off surfaces — a flickering torch pool (dims + warm-shifts + gutters as `torchFuel` runs low; a **steady** faint eyes-only ember when unlit), per-tile-flickering fire, a gold Sunblade glow, cold-violet altars, teal **glowcap fungi** (bioluminescent grotto terrain that IS a light source — a dark `cavern` region navigable by its own glow), a boss aura, a pulsing red underlight on the lich's telegraphed barrage, and transient bolt/blast/hit flashes fed from the FX layer (`fxLights`). Each visible tile's glyph color is multiplied by (**per-biome ambient** + computed light) in the single `litVis` choke point; the ambient eases from a biome center-tint at the player to a ~fog-level edge floor (so a visible tile never reads darker than explored memory — no black ring at the vision rim). `explored` = darker memory, unseen = black; a throttled ambient rAF loop (`AMBIENT_MS`) drives the flicker + recomputes the light map; visible **water shimmers** and **marsh reeds sway** on the same loop (all off under `prefers-reduced-motion`, which also freezes the light steady). All lighting tuning (ambient tints, source colors, reflectivity, passes) lives at the top of `lighting.ts`. **Set-piece lighting beats** modulate the per-region ambient off existing triggers (all in `renderBase`, cresting with the danger-music swell). Two use `LevelConfig.lightingBeat` with a gentle pulse, but DIFFERENT triggers (the levels are shaped differently): **`"dawn"`** (Throne) is keyed to Malachar's remaining HP — his multi-phase fight IS the level, so the hall warms + brightens toward a rekindled sunrise as his HP drains, cresting on the kill (the quest's payoff); **`"dusk"`** (Antechamber) is keyed to how far the player has **advanced toward the Herald** (the gate) — `1 − dist(player,boss)/dist(entry,boss)` — NOT his HP, because the Herald dies fast and the level then transitions, so an HP-keyed dusk would bottom out for only the instant before you leave; distance-keyed, the dim/cool deepens across the whole approach and peaks as you reach him. The color transform itself is the pure, unit-tested `beatAmbient(beat, g, ambient)` in `lighting.ts` (renderBase computes the eased intensity `g` and maps it over each region's ambient). The third: the **Sunken Crypt darkens + cools** as its flood rises (`floodStep`). Cosmetic FX (via `effectBus` → `CanvasRenderer.playEffects`): `projectile` (head + fading trail), `hit` (white→ember spark), `blast` (expanding ring of sparks over the firebomb/Ruin radius) are canvas-drawn on the fx rAF loop; `damage` spawns a DOM `.dmg-num` that floats up and fades (red toward the player, gold toward monsters; anchored via the canvas's `offsetLeft/Top`; skipped under reduced-motion). A second **transparent overlay canvas** sits exactly atop the rot.js canvas (created in the renderer's constructor, sized/positioned + scrolled in lockstep each `paintOverlay`) and carries the effects the cell grid can't: (a) additive **bloom** (`paintBloom`) — soft radial-gradient halos on the brightest sources (fire, the Sunblade, glowcap fungi, in-flight bolts) blended with `globalCompositeOperation="lighter"` so they radiate; plus **per-biome atmosphere** (`BIOME_ATMOSPHERE` in `tiles.ts` → `paintAtmosphere`): drifting mist blobs (marsh/crypt), snow (mountain), rising embers (throne), dust motes (castle), drifting glow-spores (cavern) — procedural from the clock, off under reduced-motion. A level may also set **`LevelConfig.weather`** to override its base-biome atmosphere: **`"rain"`** = gentle falling rain streaks (the cursed **Blackwood**), **`"storm"`** = heavier rain PLUS periodic **lightning** flashes (`paintLightning` — a clock-driven white flash over the visible scene, main strike + aftershock; gated on `"storm"` only) on the exposed **Ramparts**. Both map through `WEATHER_ATMOSPHERE`. Bloom + atmosphere are then clipped together to the visible FOV set (one-fill `destination-in` in `clipToVisible`) so nothing bleeds past walls or into unseen tiles; and (b) cracked-wall **knockout fissures** painted in the background color (`#0d0d0d`) that cut through the wall glyph so it reads as fractured (per-tile-deterministic shape; needed because rot.js allows only one fg color per cell). The overlay sits _above_ the glyphs (the base canvas is opaque), so light is additive rather than occluding. **Persistent decals** (`GameState.decals`, index → `"scorch"`|`"blood"`; scorch stamped when a fire tile burns out, blood when a monster dies via `awardKill`; capped by `CONFIG.maxDecals`) are drawn on the overlay as soft **organic blobs** (`drawDecal` — a seeded rotated/squashed radial-gradient oval + splatter droplets for blood), clipped to the visible FOV with the bloom. HUD overlays on the map region: `BossBar` (prominent HP bar shown while a boss — `isBoss` — is in `visible`), `EliteBars` (compact top-left HP bars for tough non-boss threats in view — champion elites and `MonsterDef.miniBoss` guards like the Gate Warden; capped at 4), and `LevelIntro` (a title+goal card that fades in when a level opens, then unmounts on a timer — it remounts because the canvas region unmounts during narration/shop). ASCII art (`AsciiArt`) supports flat color, CSS `gradient`, per-row `lineColors`, or per-region inline `{key}` `colors` tokens (tokens are zero-width → alignment safe); parents use `text-center`, so `.ascii` forces `text-align:left` to keep columns.

a **knockback** weapon slams a monster clean through one (instant); or the player **melee-bashes** an adjacent one, which crumbles after `CONFIG.crackedWallToughness` bumps (progress tracked in `GameState.crackedWallHits`); Most monsters treat a shut door as a wall and reroute; `MonsterDef.opensDoors` foes (goblin, Gate Warden, Herald, Malachar) spend a turn forcing it (door-aware `stepToward`). Doors generate open so all connectivity/trap-free guarantees are unaffected; a door creak plays via the `door` `GameEvent`. **Forage** (`TileType "forage"`, `LevelConfig.forageCount`, placed in nooks off the beeline via `placeForage`) — walkable heal tiles: step on one to recover a little HP (`forageStyle(biome)` in `config.ts` → outdoor berries/mushrooms +1, arcane motes +2; generous outdoors, sparse in the castle, none in the throne), then it's spent to floor; skipped at full HP (left for later); floats a green `+N` via the `heal` `GameEvent`. **Elite/champion monsters** (`MonsterInstance.elite`, table in `content/monsters.ts` `ELITE`; rolled at spawn per `LevelConfig.eliteChance`, never on bosses) come in three flavors — **brute** (tankier + hits harder), **swift** (acts twice/turn), **volatile** (bursts on death for `CONFIG.eliteExplodeDamage`); they pay double coins and always drop loot, and render in a champion tint. **Stealth via light**: monster detection is capped at `min(sightRadius, player.lightRadius, shadow?CONFIG.shadowSightRadius:∞)` (FOV is already light-limited), so dousing/low light/Shadowcloak lets you approach unseen; striking a chaser still in its `idle` state is a **sneak attack** (`CONFIG.sneakMultiplier`). Alerted monsters aren't omniscient: while they can't detect you they hunt your **last-seen tile** (`MonsterInstance.lastSeen`) and, after `CONFIG.loseInterestTurns` with no contact, **give up** back to `idle` (`lostTurns`) — so breaking line-of-sight (a corner, a shut door, dousing light, a blink) and waiting actually shakes a pursuer. Bosses (`isBoss`) never lose interest and always track your true position. **Equipped ranged weapons** (`ItemDef.ranged = {range, ammoId}`, e.g. the Hunter's Bow + `am_arrow` ammo bundles): while a bow is equipped, attacks fire arrows — bump = point-blank shot, `f`/Fire opens the shared cursor (`TargetingData.kind: "ranged"`) to loose at a tile in range + LOS (`shootAt` action), each shot spends one arrow; out of arrows falls back to a feeble 1-dmg jab. **Altars/shrines** (`GameState.altars`, `LevelConfig.altarCount`; behavior/text in `src/game/core/altar.ts`) sit on **walkable** floor (they never block a route — the offer opens _after_ you step onto an unspent one, so declining just walks you past) — landing on one opens the `altar` UI mode with a single pre-rolled bargain (vigor: gold→+maxHP; **warblood**: −maxHP→permanent `PlayerState.weaponBonus`; hoard: HP→potions+gold); `applyAltar` (pure) pays the cost + grants the boon. **Environmental storytelling** (`GameState.lore`, `LevelConfig.loreCount`, text in `src/content/lore.ts` `LORE_POOLS` keyed by biome) — readable **lore props** (walkable `¶` glyphs, gold; `placeLore` tucks them into NOOKS off the beeline via `openOrthoCount ≤ 2`, each a DISTINCT fragment from the level biome's pool, text stored inline so it roundtrips in the save) reward curiosity with STORY, not loot: step onto an unread one and the store opens a read-only `lore` UI mode (`LoreModal`; marks it `read` so it won't reopen + dims the glyph), no cost/boon — same "step-onto-POI → modal" flow as altars (Enter/Esc dismiss). Flood levels protect lore tiles in the plan (like altars) so an inscription never drowns unreadable; the fragments deepen the Ember-of-Dawn / Malachar arc (prisoners' scratchings, the Sunblade's rifled tomb, a servant's diary, the words at the base of the throne). **Ambient wildlife** (`MonsterBehavior "ambient"`, placed via `LevelConfig.ambient: {monsterId,count}[]` OUTSIDE the combat `monsterBudget`) — non-hostile creatures that make the world feel alive, not a kill-grid: they **drift** idly and **flee** when you come within their shy radius (`driftAmbient` — never step onto you, never attack, deal 0 damage), and bumping one **disperses** it harmlessly (removed with a shimmer — no combat, coins, loot, or kill credit; `movePlayer` intercepts before the attack path). The **Will-o'-Wisp** (`wisp`, on the Blackwood) is also a small drifting **light source** (`WISP_LIGHT` + a bloom halo) — pale lights that lure you off the path deeper into the cursed wood. **Boss fight** — Malachar (`behavior: "bossLich"`, tuned in `CONFIG.lich`) fights in three HP-gated **phases** (>2/3, >1/3, ≤1/3) that escalate ability frequency/scale: he hurls bolts, **summons** clusters of risen dead around himself (skeletons/wraiths, capped), rains a **telegraphed dark-fire barrage** (`GameState.barrage` tiles are marked one turn, then `resolveBarrage` detonates them at the top of the next monster phase — one turn to step clear), and **blinks away** (`lichTeleport`) when cornered to melee from phase 2 on. The barrage telegraph renders as a pulsing danger cell in `CanvasRenderer`. **Character classes** (`src/content/classes.ts`) — New Game opens a `classSelect` screen (1/2/3 or click; Esc backs to the splash) to pick **Warrior** (Short Sword + Leather, 26 HP, `damageReduction` 1), **Rogue** (Dagger, 16 HP, `sneakMultiplier` 3 + `critChance` 0.2), or **Pyromancer** (Bow + arrows + firebombs, `bombPower` +6). `createPlayer(classId)` applies the kit + `PlayerState.classId`; passives are read at their sites — DR via the shared `mitigate` choke point in `combat.ts` (enemy melee + bolts, not hazards), sneak/crit in `resolvePlayerAttack`, bomb bonus in `detonateAt`. The neutral `"wanderer"` class (not in the picker) is the plain baseline for `createPlayer()` with no arg. Each class carries an icon (`ClassDef.glyph` — Warrior ⚔ / Rogue † / Pyromancer ✷) shown on the picker card and as a colored badge in the HUD header. **Class active abilities** (`ClassDef.ability`, bound to `[q]`, on a turn cooldown — `PlayerState.abilityCooldown`, ticked in `resolveTurn` except the use-turn): Warrior **Cleave** (`aim:"none"` — one sweep hits every adjacent monster via `resolvePlayerAttack`), Rogue **Dash** (`aim:"dir"` — leap up to 3 tiles, landing fully like a blink), Pyromancer **Scorch** (`aim:"dir"` — a widening cone of `igniteTile` fire). The `{type:"ability", dx?, dy?}` action routes through `useAbility`; directional ones open a lightweight aim (`triggerAbility` → `targeting` cursor `kind:"ability"`, and the **next movement key IS the direction** — no tile confirm), rendered as cardinal arrows around the `@` (not the firebomb reticle). Surfaced in the HUD loadout row + Help; effect balance lives in the ability functions / `classes.ts`. **Run modifiers** (`src/content/mutators.ts`) — opt-in, seeded "trials" chosen after class select (a `mutators` UI mode + `MutatorSelect` toggle-any screen; `store.selectedMutators` → `beginRun`) that reshape the WHOLE run. Each is a pure transform: `applyLevelMutators(config, ids)` runs in `beginLevel` **before** generation (light/spawns/traps/turn-budget/elites — so all generator guarantees still hold), and `applyPlayerMutators` does one-time run-start tweaks (Glass → 1 life). The active ids live on `GameState.mutators` (threaded through every level transition, roundtrips in the save) and raise the end-of-run **score** (`mutatorScoreMult`, shown on `RunStats`); a `⚠ N` HUD badge lists them. Current set: The Dark Deepens / Restless Dead / Treacherous / Forsaken (no forage + scarcer drops) / Champions / Glass. The playthrough bot never selects them, so the balance table reflects unmodified runs.

**Sub-biome regions & secret vaults** — `GameMap.region`/`regionBiome`/`regionPalette` tag tiles with a region id (0 = the level's own biome; JSON-safe `number[]` so they roundtrip in the save). `generate.ts` `carveSubBiome` shapes an optional `LevelConfig.subBiomes[]` (an ARRAY — a level can host several regions, each getting the next region id 1, 2, …) two ways per entry: an organic **Simplex-noise blob** (`carveSubBiomeBlob` — cosmetic, never touches tiles) or a rectangular **wing whose _structure_ is a secondary generator** (`carveSubBiomeWing` + `spec.layout`, e.g. a `maze` catacomb — bridged to the main map by cleared cross-arteries so the perfect maze stays navigable). `scatterRegionHazards` fills the region with a **hazard kit** (`spec.hazards[]` — a bog's `water` pools, a scorched hollow's `oil`, a grotto's glowing `glowcap` fungi, …; omit to inherit a per-biome default from `BIOME_HAZARDS`) as scattered specks, or as a few flood-grown contiguous **pockets** via `clumps` (e.g. one glowing fungal hollow) — all carved **before** the connectivity pass, so `largestFloorComponent`/`sealUnreachable`/`ensureTrapsAvoidable` guarantees still hold (a severed pocket is just abandoned). New `GeneratorKind`s — `rogue`, `maze` (`DividedMaze`), and custom `hall` (a cathedral nave, `genHall`) + `rampart` (a linear wall-walk, `genRampart`) + `gallery` (a processional statue gallery — promenade + double colonnade + niches, `genGallery`) — join `digger`/`uniform`/`cellular` via the shared `genGrid` helper, whole-level-capable too. **Secret vaults** (`LevelConfig.secretVault`, `placeSecretVault`) carve a fully-walled room holding loot, reachable ONLY through a single **gate** — a **cracked wall** to blast/bash (`gate:"crackedWall"`, default) or a shut **door** to simply open (`gate:"door"`, e.g. a dungeon cell / castle strongroom / crypt reliquary — reads right in stone/dungeon wall mass). Carved AFTER normal placement so it's a separate floor component (spawns never leak in), and it survives `sealUnreachable` because both cracked walls and shut doors count as passable in that flood (`isOpenTile`) — kept, but physically gated until you break/open in. **Freestanding structures** (`LevelConfig.structures[]`, `placeStructures`) are the OUTDOOR counterpart: instead of digging a room into existing wall, they stamp visible **wall boxes** (a floor interior + one shut door + loot) onto open clearings — a hut in the woods, a shrine in a field, where a dug-in door would just look like a floating door. It's an ARRAY, so several entries read as a **hamlet** (each stamped in turn, re-scanning for its own clearing so they never overlap). Stamped BEFORE the component pass (so the door-sealed interiors drop out of `largestFloorComponent` → no spawns inside) and required to sit in an all-floor footprint + 1-tile margin (a clearing) **on the main reachable component** (never an isolated pocket, or `sealUnreachable` would wall the hut + loot away), so it never severs a corridor; a few footprint sizes are tried before giving up. Because stamping huts can flip which floor component is "largest" on a fragmented map, structure levels then anchor the player+spawn `floors` to the SAME component the huts opened onto (`floorComponentFrom`), never merely the largest — otherwise player and huts could end up in different regions. The footprint is tagged its **own cosmetic region** (biome `dungeon` + a palette — warm timber by default, overridable per structure via `spec.palette`, e.g. mossy or cold stone) so the walls render as a built `#` distinct from the surrounding biome's wall glyph (the door keeps its tile-based gold `+`) — region is purely visual, tile TYPES still drive every mechanic. The renderer resolves each tile's biome/palette **per region** — `terrainGlyph`/`terrainColor`, the lighting ambient in `litVis`, and `paintAtmosphere` (which gates each biome's weather to its own region's cells, scattering a sub-region's particles across just that patch). Currently every level carries a signature terrain beat: the **Pit** (a deliberately larger opening level, 56×34) a `cellular` natural **cavern** wing (`cavern` biome, readable rock walls) holding **several** glowing **fungal hollows** — contiguous `glowcap` pockets (`clumps: 3`) that light it (navigate toward the teal glow) + a door-gated cell; the **Blackwood** (a big 84×52 wood to roam) a boggy marsh sub-biome (water pools), a bright **glade**, a thorn-choked **briar** (`bramble` thickets — snag/bleed you; burn a path through), drifting **will-o'-wisps** (harmless `ambient` lights that flee as you near — see below), AND a ruined woodcutters' **hamlet** (`structures[]` — five varied huts of mixed small sizes and loot, some empty/ransacked, the shards scattered among them); the **Mire** a big sprawling **wetland** (72×46) — water channels to weave, dry grassy **hummocks** (islands), a reed-thicket `maze` wing (a green `♠` labyrinth), poison-**spore vents** (`sporeVentCount` — fumaroles seeping a toxic haze to skirt), and a lone mossy **wayshrine**; the **Frostspine** a big `cellular` mountain **cave network** (72×46) choked with impassable **crevasses** — frozen tarns (`water`, Rimewalk can freeze a bridge) AND bottomless **chasms** (`chasm`, only Levitation crosses) — plus two frozen **ice grottos** and a ruined border **watchpost**; the **Iron Gate** a `rogue`-generated **gatehouse** (a grid of connected guard chambers — a distinct floor-plan from the winding digger halls) with an oil **scorched hollow** (an Emberstep region); the **Great Hall** a `hall`-generated **cathedral** — a dominant colonnaded central nave with flanking side-chapels, lightly varied per seed (proportion jitter, an optional crossing transept, an occasional chapel collapsed into a `chasm`) so no two runs match while staying recognizable — + a door-gated **strongroom**; the **Sunken Crypt** a catacomb `maze` wing + a bioluminescent **fungal hollow** (glowing `glowcap` islands that stay dry+lit as the black water rises — the crypt's dark makes them blaze) that **floods** as you hunt the Sunblade (below); the **Ramparts** a `rampart`-generated **wall-walk** — a long exposed battlement with a bottomless `chasm` void beyond a crenellated parapet (shove the dead through the embrasures) and inner **tower rooms** to fall back to, lashed by a lightning **storm** and glazed with **ice**; the **Antechamber** a `gallery`-generated processional **statue gallery** (`genGallery`) — a wide central promenade flanked by a double **colonnade** of statue plinths + side aisles behind the pillars (flank / break LOS), patrolled by gargoyle "**statues**" (`guardChase` — still as stone until you draw near, then they wake and shove) — plus a door-gated **reliquary**. Varied per seed: the **statue niches** recessed in the outer walls are per-bay randomized (~30% solid, the rest 1–2-deep alcoves, ~40% of the deep ones **cracked-wall-gated** with an "offering" cache tucked in the back — placed by scanning niche dead-ends, reachable by bashing in), and ~half of seeds drop a **collapsed** section (an interior `chasm` pit with a ragged/eroded outline — the perimeter is crumbled off so it reads as a give-way, not a clean rectangle; kept off the spine so you route around it, but a gargoyle can shove you in).

**Flooding set-piece** (`LevelConfig.flood` + `tickFlood`) — a level fills with water during play. `computeFloodPlan` marks a protected dry **spine** (shortest path start→objectives AND to every altar, dilated one tile) that never floods, so the goal — and each interactive altar — stays reachable throughout (verified even at full submersion; an unprotected altar would drown into water yet still render its `+`, stranded); everything else rises one ring every `interval` turns (from `startTurn`, capped at `maxSteps`) from **seeds spread across the whole near→far range** (count scaled to the floodable area) so the water wells up all over — including just off your route — rather than as one distant tide you never see; never floods onto an occupied tile. Water flows THROUGH an **open door** but a door pulled shut (`[c]`) **holds it back** — non-protected `doorOpen` tiles are floodable, a closed `door` is not (checked live in `tickFlood`), so shutting a door dams the flood down that corridor (player agency against getting boxed in). Water is impassable, so **Levitation** glides and **Rimewalk** freezes a path — the terrain-defying draughts become clutch. `GameState.floodable`/`floodSeeds`/`floodStep` (JSON-safe) drive + persist it. Live on the Sunken Crypt. **Set-pieces scale**: the Great Hall is a deliberately larger, _sparse_ map (grandeur, not a grind — density tuned down; since the turn limit is now just a par-for-score target, size no longer fights a turn-budget guard).
