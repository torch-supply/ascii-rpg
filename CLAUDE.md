# Ember of Dawn — ASCII RPG

A single-player, browser-based ASCII RPG. Next.js (App Router) + TypeScript, **client-only** (no backend; static export to `out/`), rendered with **rot.js** on a canvas, styled with **Tailwind v4**, state in **Zustand**.

## Run

- `npm run test:core` — pure-engine checks (determinism, goals, combat, connectivity, and Phase 2/3 mechanics: status effects, fire/oil, elites, stealth, ranged, altars, cracked-wall demolition, decals, shop selling, the survive siege, class active abilities, run modifiers, par-for-score bonus, a par-reachability floor, flood set-piece (altars stay reachable, doors dam the water), chasm falls (shover knockback into the void), bramble (snag-bleed + fire clears it), spore vents (bounded poison haze), lore props (placed/distinct/reachable), ambient wisps (flee/harmless/disperse), the gallery generator (niche offerings, varied collapsed pit, and the narthex/apse + flanking chambers that give the hall a plan), organic vs. built wings (the Mire's reeds grown, the crypt's catacombs still masonry), where a run may begin (`noStart` regions + the start→exit floor), glyph uniqueness across categories, light-gated sight driving `state.visible` (incl. shooting what you can see), atmosphere tracking the light, status resistance (an ice troll shrugging off chill), the dawn/dusk ambient beat (`beatAmbient` warms vs. dims by intensity), all-placed-items reachability incl. gated hut/vault loot, and that **every run modifier preserves the generator guarantees** (each trial + the all-on stack × levels × seeds: objectives reachable, no orphaned pockets, a trap-free route survives Treacherous)) via `scripts/verify-core.mts`. Tests mechanics in **isolation** (one hand-built scenario per check).
- `npm run test:play` — **autonomous-playthrough / balance harness** (`scripts/verify-playthrough.mts`): a greedy bot (real class kit + the shop consumables a player buys — heals & firebombs — no god-mode) plays every level across many seeds and asserts no invariant violations during real play, navigation/attrition levels are bot-beatable, boss/siege levels are enterable (not instant wipes), and outcomes are deterministic. The bot bump-attacks, auto-heals when low, hurls firebombs at bosses/clusters (kiting to reopen bombing distance), fires an equipped bow, **equips upgrades it picks up**, **fires its class ability** (`[q]` — Cleave into a crowd, Scorch down the fullest cone, Dash out of one), and **flees to open ground on survive levels / when surrounded**, so boss & siege win-rates are a real (if conservative) signal of the intended toolkit, not just pure melee. (Adding equip+ability moved real numbers: Rogue 53% → 67% once Dash actually fires, Frostspine 67% → 83%, Great Hall 50% → 67%.)
- `npm run test:store` — **store-level orchestration harness** (`scripts/verify-store.mts`): drives the vanilla Zustand store (`gameStore`) headlessly to assert the LoopDriver's run/screen flow — boot (splash→class→opening narration→play), the anti-skip input-settle guard, level-clear→narration→shop→next-level ordering, shop economy (buy coin/qty caps + sell), death→restart-level vs. last-life→game-over, final-level→victory, the lore-prop interaction flow (step onto → read modal → dismiss → stays read), the save/resume roundtrip, bag hotkeys acting during play against stable slots, and **overflow past the nine keys staying usable** (14 slot-eligible item types vs 9 hotkeys: past the ninth there is no key and no panel row, so the `[i]` sheet's rows are the only route — `[S17]`, which also source-checks that wiring, because every behavioural assertion around it drives the store directly and would stay green if the row stopped being a button).
- `npm run test:soak` — **generation soak** (`scripts/verify-soak.mts`): the structural guarantees across every level × **200 seeds** by default (`npm run test:soak -- 1000` before a release; 10,000 generations ≈ 30s). The fast suite checks each guarantee on 5–8 hand-picked seeds, which is the right shape for a per-commit gate but blind to the tail — and a procedural generator fails on _rare_ seeds, which is exactly what reaches a player. Checks connectivity (no orphaned open tiles), objectives + all placed items reachable, a trap-free route to every objective, hostile spawn distance, flood levels never marking an altar or lore prop floodable, plus sampled vault secrecy. Seeds are fixed strings (`soak-0`, `soak-1`, …) so any failure is reproducible and the report names the exact (level, seed). **Not** in `test:all` — it's a pre-release / post-generator-change gate. Verified able to fail: disabling `sealUnreachable` reddens 159/400 seeds, `ensureTrapsAvoidable` 16/400.
- `npm run test:all` — runs all three fast suites in sequence (core + play + store; soak is separate).
- `npm run lint` / `lint:fix` — ESLint (flat config `eslint.config.mjs`: `eslint-config-next` core-web-vitals + typescript, with `eslint-config-prettier` last; React-hooks rules off for the pure `src/game/**` + `scripts/**`). `npm run format` / `format:check` — Prettier (`.prettierrc`, double quotes). A **husky pre-commit hook** (`.husky/pre-commit` → `lint-staged`) runs Prettier `--write` **then** ESLint (no `--fix`, so a lint error fails the commit) on staged files.
- Per-check rationale, mutation-audit findings, and the traps to avoid when writing or debugging these suites: `scripts/CLAUDE.md` (loads automatically when working under `scripts/`).

**Dev tooling** (gated on `DEV = process.env.NODE_ENV !== "production"`, so it's absent from the static build): the splash shows a **level picker** that jumps into any level with a tier-appropriate loadout (`store.debugJumpTo`), and in play `>` skips to the next level (`debugSkipLevel`). **`/style`** (`app/style/page.tsx` → `screens/StyleGallery.tsx`) is a dev-only **visual reference**, and the place to sanity-check anything visual. Sections: **tiles × biomes** as actually rendered; **POIs & overlays** (altar unspent/spent, lore inscription/remains/read, fire burning/guttering, gas, the barrage telegraph, `@`) — these are drawn OVER the grid and aren't `TileType`s, so they'd otherwise be invisible here; **lit vs. remembered** (fog ×`FOG_DIM`, since a color can read when lit yet vanish from memory); a **glyph-collision report** (one character meaning two things — it reads the RENDERED glyph via `terrainGlyph`, not the raw table, and labels deliberate collisions like floor/trap, wall/crackedWall and the per-CLASS item glyphs as intentional so a real one isn't buried). **Its input is the whole screen, not just terrain**: it compared only terrain against monsters for a long time, and so read clean while `∴` meant both a healing arcane mote and a cloud of poison, and `‼` for a wall sconce was two of the `!` that twelve potions share. Items, class badges, the player and every overlay are fed in now, and all three are fixed: the mote moved to `❖`, the sconce to `Ω`, and guttering fire to `▵`. What remains colliding is entirely WITHIN one category (twelve potions on `!`, seven weapons on `/`, the two quest items on `*` — which never coexist on a level), plus `✷` for the barrage vs. the Pyromancer badge, which is HUD chrome and never drawn on the map; biome palettes/ambients/atmospheres; monsters; class badges; items; **one monster under every tint it can wear** (species / elite / debuff); decals; weather; and the **activity log** — every message kind rendered on the real rail plate, with the AA ratio and colour distance beside it, plus each status affliction shown BOTH ways ("You are poisoned!" vs "The Skeleton is poisoned!") because that pair is the distinction the classifier most easily gets wrong. Its sample lines are lifted from the real message templates, not invented prose: the classifier is a heuristic over that text, so a made-up sample would prove nothing. Everything carries a live contrast reading (red &lt;110 / amber &lt;200 / green). It owns its own scroll container because `globals.css` sets `body { overflow: hidden }` for the game. It exists because the visual bugs that shipped were only ever caught by eye, late, after playing to the level that showed them; this makes that pass instant and systematic. Test `[54]` enforces the numeric floors, the gallery covers the judgement calls it can't.

## Architecture — one-directional data flow

```
KeyboardInput → store.handleCommand → store.submitAction (the turn-based LoopDriver)
   → pure core transitions (resolveTurn) → new GameState
       ├→ React HUD/screens (Zustand selectors)
       └→ rot.js CanvasRenderer (store.subscribe)  +  cosmetic effects via effectBus
```

React and the canvas are **read-only consumers** of state. No timing lives in the core — that keeps a future turn-based→real-time swap contained (replace `submitAction`/`LoopDriver`, add tweening; core/renderer/save untouched).

### Load-bearing rules

1. **Two RNG streams** (`src/game/core/rng.ts`). Map geometry is seeded from the GLOBAL `ROT.RNG` via `seedMapGen(levelSeed(master, index))` — a pure function of seed+index. Gameplay uses a separate cloned `Rng` whose state is persisted in the save. Never let them share.
2. **Canvas is client-only.** `src/app/page.tsx` dynamically imports `GameRoot` with `ssr:false`; `ROT.Display` is created in a `useEffect` and appended to a React-owned div. React never reconciles canvas contents.
3. **Pure core.** `src/game/core/**` has no React/Zustand/DOM imports.
4. **Light is CORE, not render** (`src/game/core/light.ts`). Sight is line-of-sight to `CONFIG.sightRange` filtered by what is actually LIT above `CONFIG.sightLightMin`, plus `SKYLIGHT` under an open sky and `CONFIG.unlitSight` in the pitch dark — and `recomputeFOV` computes exactly that, so **`state.visible` IS the light-gated set**.
   - It lived in `src/render/` as a probe, with the renderer keeping a private visible-set AND a private fog memory. The two models then disagreed everywhere downstream: `shootAt` gates on `state.visible`, so you could see a lit room and be **refused the shot — silently, no message, no turn spent**; a boss in plain sight got no HP bar and no musical sting; a monster you were watching died of poison with no message; `dangerIntensity` and the stealth "held breath" cue couldn't react. The renderer's memory was neither saved (resuming showed an unexplored map) nor reset per attempt (keyed on level index only, so a death-restart handed you a level already mapped). Test `[70]` reproduces the shooting bug the moment `sight` is flipped back to `"torch"`.
   - **Flicker is not visibility.** `computeLightMap` is shared, but the core always calls it STEADY (`now = 0`, `reduceMotion`, no FX) — a torch guttering at 60fps must not make tiles wink in and out of `state.visible`. The renderer layers flicker and transient FX on top for COLOUR only.
   - **Stealth was untouched by the promotion**, which is what made it safe: detection reads `player.lightRadius` directly (`min(def.sightRadius, p.lightRadius, …)`), never `state.visible`. Dousing your torch still hides you — you just now see the lit room ahead while you do it. The knock-on: a check that asserted "the player can't see it" as a proxy for "it can't detect the player" had to become behavioural, because light-gating split those two apart.
   - **A light source's strength is now a VISIBILITY decision, so weak ones are bugs.** `BOSS_LIGHT` was luma 58 against a `sightLightMin` of 55 — it cleared the bar by three, on the boss's own tile and nowhere else. The boss therefore revealed itself from anywhere in line of sight while illuminating ZERO tiles: the exact inverse of the "cold necrotic glow that precedes it into a room" it was written to be. Violet hides this well, because luma weighs blue at only 0.0722, so a saturated violet is dim by construction. At `[160, 130, 255]` (luma 145) the aura reaches 3 tiles and lights ~20 — brighter than an altar, as a boss should be — and the dread now arrives before the shape does. Test `[70]` pins it; with the old value it reports "1 tiles". **Check any new light against the table in `light.ts` and against `sightLightMin` before trusting it** — the same mistake sank the first light-shaft attempt, whose tint was dimmer than the bare torchless ember.
   - **World light and carried light are TWO fields** (`CONFIG.worldLightRange` vs your `lightRadius`), summed. `ROT.Lighting` exposes a single `range` and its falloff is `1 - r/range` measured FROM THE SOURCE, so one shared range let the player's torch dictate the size _and_ brightness of every other light on the map: measured on the Great Hall, striking a lantern took far-off lit tiles from 343 to **720** — your torch was more than doubling the light coming off braziers across the level. `worldLightRange` is 5 because that reproduces the old look in the case where the bug was dormant (torch out), while removing the inflation: the Antechamber used to go 104 → 193 visible tiles on lighting a torch and now goes 104 → 144, which is your own pool growing rather than the whole castle brightening. It is the dial for how far a light carries.
   - **Only a carried flame flickers, and daylight drowns it** (`torchFlickerDepth`, shared by the light map and the renderer's torch-edge wobble so they can't drift). Zero without a lit torch — the torchless ember is your own eyes adjusting, and if it wavers the darkness itself appears to pulse, which reads as a rendering fault. Full depth indoors (0.20, rising to ~0.54 as the fuel gutters), damped by `SKYLIGHT` to near nothing outdoors (mountain 0.000, marsh 0.018, forest/graveyard 0.036). It resolves PER TILE, so on the Iron Gate the flame is imperceptible out on the graves (0.036) and starts guttering the moment you step into the gatehouse (0.200). Per-source too, via `ItemDef.flicker` (1 = a bare flame, the **Lantern** 0.35): a glassed flame wavers less, and the multiplier scales the WHOLE curve so a lantern down to its last oil still falters but never as wildly as a torch burning out. Measured on-screen swing — torch 12.3% healthy / 23.5% guttering, lantern 4.1% / 7.8% — which makes a guttering lantern calmer than a _healthy_ torch, deliberately. That gives the lantern the reason to exist it was missing: its upgrade used to be purely numeric (one more tile, longer fuel), both read off the HUD and never felt, and steadiness is the part you notice without being told.
   - **Atmosphere had to follow the light too.** Weather particles are masked to `state.visible`, which is no longer a torch disc — a tile can be visible on SKYLIGHT alone with nothing in the light map. Their alpha was a flat constant, which was only safe while everything visible was lit, and the Frostspine showed the cost: 57% of its visible tiles dim or unlit, with snow at particle luma 130 over ground at 93, making the snow the brightest thing on screen across half the view. A REFLECTIVE mote (snow/rain/ash/dust/mist) now scales with the tile's rendered luma — the same `tileLight` the glyph uses, so the two can't drift — landing at 63 on unlit ground and back to full inside a torch pool. `ATMO_EMISSIVE` (embers, spores) is exempt and LOCKED by test `[71]`, because the cheapest way to silence the brightness rule is to declare the offending kind luminous.
   - **A biome in play needs something in its air.** Checking that found three vacuums: `graveyard` (a base biome — 74% of the Iron Gate, open sky, perfectly still), `sanctum` (a roofless flooded ruin), and `forest` — which hid because the Blackwood's level-wide `weather: "rain"` covers the base biome, so nobody noticed the Mire's dry hummocks are the same `forest` biome as a SUB-region and sat motionless inside a bog full of moving vapour. `dungeon` is the one deliberate exception (a sealed cell, and the tag a hut's walls borrow).
   - **Sconces moved to generation** (`placeSconces` → `GameMap.sconces`) for the same reason: a bracket is often the only thing making a distant room visible, so `recomputeFOV` needs it. Placement is a hash of the level index, so it consumes no map-gen RNG and every level lights as before.
   - Cost is 0.06–0.55 ms/turn against 0.006–0.018 for the old radius FOV — ~30× more, and irrelevant at one call per turn. Measured effect: the bot's `medSeen` rose almost everywhere (Iron Gate 26%→39%), and at 40 seeds win-rates were neutral on six levels and **easier on three** (Great Hall 65→75%, Ramparts 53→63%, Antechamber 50→63%) — an outstanding balance item, deliberately not retuned.
     `resolveTurn` (`src/game/core/actions/index.ts`) mutates a GameState and returns a `TurnResult` (including cosmetic `events` for the animation layer — animations NEVER touch game state).

The first version listed allowed _glyphs_ and could not tell that fixing `*` had worked, because the two quest items still share it between themselves: the glyph kept colliding for a harmless reason and the entry looked live. Locking the set means a new cross-category collision reddens AND delisting is forced when one is fixed, so the list can't become a graveyard of accepted bugs. It cannot catch a NEAR-miss (`‼` vs `!` are different codepoints and compare clean) — that is what the gallery showing them side by side is for. It also only covers glyphs that PERSIST on the map: the blast sparks in `fxCells` still draw `*`, which is idiomatic for an explosion and lasts a few frames, so it is left alone deliberately rather than overlooked.

On/off persisted in localStorage; `store.soundOn`/`toggleSound`, `[m]` key + a shared `SoundToggle` button (HUD footer + splash top-right
  - `music.ts` — procedural background music — a detuned drone pad + sparse chorused melody + rare high "sparkle" bells on a per-biome scale (lookahead scheduler), plus a per-biome **ambient texture bed** (`noiseGrain` — overlapping filtered-noise swells for wind/rumble + sparse drips/crackle; open-air biomes (forest/mountain) use `bed.gust` mode — spaced, randomly-timed breeze gusts with quiet lulls rather than a metronomic overlap) and per-biome **timbre** (note low-pass `cutoff`) + **reverb** (echo retuned per track via `setMusicEcho`) through the music-bus feedback delay for an ethereal, place-specific wash; per-biome **instrument voice** (`Track.voice` → `voiceNote`: an envelope shape — plucked harp for the forest, slow bowed swell for the mire, airy bowed for the mountain, grand strings for the throne — plus optional inharmonic `partials` for a struck **bell**, the crypt + cavern) so each biome has its own melodic instrument; a distant wordless **choir** (`Track.choir` → `choirVoice`: a sawtooth sung through two vowel-formant bandpasses with a slow swell + vibrato, laid under the drone) in the haunted castle biomes (castle "ah" / crypt dark "oo" / throne full "ah" — Blackhall's massed dead); a cozy major shop theme; a grand **title/menu theme** (`TITLE_TRACK`, Dorian) on the splash

    - **stealth-reactive "held breath"** (`setMusicExposure`, fed by `musicExposure` in `GameRoot`) — when a chaser-type threat is visible but still `idle` (you're creeping past unseen) exposure falls toward 0 and the melody + sparkle thin away to just drone + wind; the instant one enters `chase` it blooms back
    - **the Ember leitmotif** (`EMBER_MOTIF`, scale-degree so it transposes into any biome's mode) — a short falling phrase woven sparsely into the melody (`Track.motifChance`, higher in the throne) as a recurring thread, resolved into MAJOR in the victory fanfare (the theme made whole)
    - **dawn/dusk harmonic beats** (`setMusicWarmth`, fed by `musicWarmth` mirroring the lighting beats' triggers) — +warmth blooms a bright major third+fifth over the drone, opens the timbre, adds sparkle (the Throne rekindling as Malachar falls); −warmth seeps a dissonant minor-second + darkens (the Antechamber's deepening dusk)
    - **evolving harmony** (`chordRoot`/`Track.progression`) — the low drone + danger pulse drift through a diatonic chord loop (`DEFAULT_PROGRESSION`, indexed into each track's own scale) rather than holding the tonic; one-shot **death** dirge + **victory** fanfare on those screens; short in-key **event stings** (`playSting`, layered OVER the running track — reads the current track's root/scale so they stay diatonic): a wistful fragment of the Ember motif on reading a **lore** prop, a cold unresolved tritone **shimmer** on accepting an **altar**, a brief resolving **cadence** on **level-clear** (triggered store-side in `acceptAltar` / the lore-open path / `handleLevelComplete`); runs on `sound.ts`'s shared context via a separate quieter music bus; `GameRoot` subscribes to the store and calls `playMusic`/`stopMusic` from `mode`+biome+`soundOn`, keeping one track flowing across intro→gameplay, and resumes the gesture-gated context on the first click/keypress (`resumeAudio`) so the title theme can start on the splash
  - `hash.ts` (`levelSeed`/`gameplaySeed` derivation), `debounce.ts`.
- `src/save/` — versioned localStorage snapshot (`schema`/`serialize`/`storage`). `src/components/` — `GameRoot`, `GameCanvas`, `hud/` (`Hud` header+footer, `LogRail`, `CharacterPanel`, the shared `Frame` / `logStyle` / `palette`), `screens/` (Splash/ClassSelect/MutatorSelect/Narration/Shop/GameOver/Victory), `overlays/` (Pause/Inventory/Help + `AltarModal`/`LoreModal` for the step-onto-POI modals), `ui/MenuButton`.

## Game systems

Feature-complete: splash → **10** procedural levels with narration → win/lose. Grouped by area;
each entry names the symbols to start from.

### Loop, goals & pacing

- Turn-based bump combat, fog-of-war, items/inventory/equip, 3 lives, save & resume.
- **Six goal types**: reach / collect / find / kill-boss / **cull** N (`killCount` — supported but unused; the Iron Gate moved to kill-boss so its big map gets traversed) / **survive** N turns vs an **escalating siege** (`maybeReinforce` spawns growing waves from a ring around the player, so you must fight/kite, not turtle). Two load-bearing details in that cap: it counts **combatants only** (`combatantCount` — ambient wildlife is placed outside `monsterBudget`, and letting the Ramparts' 3 ravens hold 3 of the slots throttled the siege; under Restless Dead, 21 combatants + 3 birds vs a flat 22 killed it outright, spawning zero waves), and it's a **floor, not a ceiling**: the effective cap is `max(CONFIG.siege.cap, monsterBudget + siege.headroom)`, so a denser level or trial gets real room to escalate into rather than being pinned at spawn. Reinforcements also roll for elite status like the garrison does (off the gameplay RNG), which is what lets Champions reach them at all. **Careful: on a survive level `monsterBudget` is not a difficulty dial in the obvious direction** — lowering it _raises_ difficulty, because the cap is the real governor and ring-spawned reinforcements arrive already in `chase` state, unlike the scattered idle garrison they replace (measured: budget 14→11 dropped the bot from 33% to 17%). Tune `siege.cap`/`headroom` or `goal.turns` instead.
- **Pacing:** the turn limit is a **par-for-score** target, NOT a threat. Only `survive` levels show a gauge (there the clock _is_ the goal); elsewhere there's no countdown and no overtime, and clearing under par grants an end-screen **efficiency bonus** (`levelParBonus` → `PlayerState.parBonus`). Running long costs nothing.
- **Arc:** dungeon → blackwood → mire → frostspine → **Blackhall Castle** (iron gate → great hall → sunken crypt → ramparts → dusk antechamber) → throne. Monsters toughen, light dwindles, par tightens.

### Economy & shop

- Between-level shop (9 tiers, one per level with a `shopTier`; buy + **sell** spare bag gear at `CONFIG.sellRate` × `sellPrice(def)`). **`ammo` is not in `SELLABLE`**, and re-adding it re-opens a money loop: ammo is the only category bought in BUNDLES (`ItemDef.value` = arrows per bundle), so a listing is 8g for twelve while `sellBagItem` pays per single arrow — and `sellPrice`'s `Math.max(1, …)` floor means no `baseValue` is low enough to close the gap (even 1g apiece sells a bundle back for 12g against 8g paid). Selling ammo needs a stack-at-bundle-rate sale, not a category flag. Test `[63]` pins the general ratio.
- **The wraith's bleed is at `chance: 0.25`, not 0.5** — and the sweep that set it is the reason to be careful with any monster carrying `inflicts`. It stacked three multipliers (high base damage, `armorPierce`, and the heaviest DoT in the game at 3/turn × 4 = 12 vs poison/burn's 8), landing 5 + 12 on a chainmail Warrior while its own spawn table — ghoul, skeleton, goblin — landed **1**. A 40-seed isolation sweep showed the bleed was doing nearly all of it: deleting it took the Great Hall 53% → 93% and the Crypt 40% → 70%, where shaving base damage 6→5 bought only +4. Two lessons beyond the number. **A DoT dwarfs the hit that delivers it** — 12 armour-ignoring damage over 4 turns is worth more than any per-hit tuning, so `inflicts` is the first dial to check on an over-performing monster, not the last. And **the balance harness cannot see `armorPierce` at all**: the bot wears the Warrior's starting leather (reduction 1), so `max(0, 1−2) === max(0, 1−1)` and pierce 2 vs 1 are byte-identical in effect. That row reading "no change" is the test being blind, not the dial being inert — measuring it needs a bot in real armour.
- **The balance harness barely sees `lootScale` or `coinPile`** — the two dials named above as the primary economy knobs. Gutting BOTH (coinPile 3–9 → 1, lootScale 0.67 → 0.2) moved the bot's whole-run purse 175g → 170g, while zeroing monster `coinReward` took it to 0 and reddened three checks at once. The bot beelines and fights, seeing only ~26–39% of a map, so ground gold is mostly never walked over and its income is almost entirely kill rewards. A row reading "no change" after a `lootScale` edit is the harness being blind to it, not the dial being inert — the same trap as `armorPierce` above. Ground loot has to be judged by placement and by play, not by `medGold`.
- **`runGold` is a sum of TWELVE-seed medians, so it is far noisier than it looks.** Across one afternoon of level-geometry work it swung 175–209g (15–18% of stock) while the same content at forty seeds held flat at 192–194g (16–17%). The affordability rail was set at 0.15, inside that noise, so it tripped on the sample; it is now 0.10, which is also the income band's own floor (120g / ~1174g) — at 0.15 an income of 120g would satisfy "stays near its tuned level" and simultaneously fail "can still afford meaningful purchases". Two guards on one quantity must agree.
- **WHAT gets hidden is a design decision, and it splits by purpose.** Ordinary loot used to scatter uniformly, so **49% of the game's items lay on open floor**: you collected them by walking the route you were walking anyway, and loot rewarded traversal rather than exploration. `placeItems` now biases to nooks — the bias `placeForage` and `placeLore` already used — but it **cannot apply to everything**. Hiding the lot took the carried-run gate from depth 3 to 2, because the balance bot beelines and never detours for loot, so it models a player who explores nothing, and that player starved. The split is by what an item is FOR: **treasure** (`coin`/`weapon`/`armor`) goes in the dead ends, because wealth should be the reward for looking; **supplies** (potions/ammo/torches) stay on the route, because running dry on heals for failing to search a corridor stub punishes the wrong thing. Measured after: treasure on open floor **49% → 5%**, supplies **92%** on the route, and whole-game placement open 49% → 23% / nook 16% → 35% / gated 15% → 23% / structure 20%.
- **Heals split by WHERE they come from, and only the exploration half is a hoard.** A run places ~19 heals, which sounds enormous against a 26 HP bar — but the number that matters is the split: **~8.4 come from the `dropTable`** (supplies place route-first, so a beeliner collects them and NEEDS them) and the rest from **`secretVault`/`structures` loot lists**, which cost a cracked wall or a hut door to reach. Cutting the route half is the obvious move and the wrong one: it starves the player who explores nothing, which is exactly the population the carried-run gate models, and that gate has no headroom. The exploration half was cut instead, 11 → 6.
  - The cut was possible because **every one of the six vaults contained a heal**, which is a variety problem before it is a balance one: breaking into a secret room always paid the same. Five became the scarcest thing in the game instead — a **situational draught**, matched to the level's own hazard (Mire → Rimewalk over its water, Frostspine → Levitation over its chasms, Iron Gate → Emberstep over its oil, Ramparts → Blinking off a linear wall-walk, Antechamber → Shadowcloak past the statues). Those five are `maxQty: 1` and only two-per-run purchasable, and **zero were findable anywhere before this** — so a vault now pays in the one currency the shop rations, and the lore vault hints have something worth following. Item COUNT per cache is unchanged, so exploration pays the same; what it pays in changed.
  - **The harness reads byte-identical across this change, and that is the expected result, not a null one.** The bot is not a looter and never breaks into a vault, so its win-rates and income cannot move — what the unchanged read verifies is the SAFETY RAIL (the beeliner's supply line and the carried-run gate are untouched), not the effect. The effect is on a player who explores, and nothing in `test:play` can see it. Verified instead by placement: all five draughts appear on 40/40 seeds and are gate-locked on 100% of them.
- **`lootScale: 0.6` is a measured floor, not a preference.** With the split in place, 0.67 and 0.60 both hold the carried-run gate at depth 3; **0.55 drops it to 2**. And that gate has NO headroom — its baseline is 2/2/3, so exactly one of three runs reaches the bar — which is why each step down was swept rather than guessed. The real leanness is placement, not count.
- **Three dials pushing one number is how you overshoot without seeing it.** Garrisons came down ~18% game-wide (146 → 120 monsters), so each remaining monster had to carry more. `coinReward` looked like the lever and was the wrong one: raised alongside richer drop tables AND higher `eliteChance`, run income hit **240g against a 193g baseline** — the opposite of lean. Backing `coinReward` out entirely landed at **188g with the carried-run gate improved** (2/2/3 → 3/2/3), because the other two were already doing the work: an elite pays double and drops guaranteed loot, so **raising `eliteChance` is itself an income raise**, and richer tables carry `c_gold`. Measure each dial before stacking the next.
- **Deliberately lean** so the shop is a real "what can I afford?" choice and attrition can cost a life. Tune the GLOBAL dials, not per-level counts: `CONFIG.lootScale` (0.6) scales ground drops, `CONFIG.forageScale` (0.5) scales wild-heal tiles (both applied in `generate.ts`, on top of any run-modifier tweak), `CONFIG.coinPile` (3–9) sizes gold piles, monster `coinReward` values stay modest, and shop heal stacks cap at `maxQty` 2.

### Generation guarantees (load-bearing)

- **Traps are always avoidable** — never beside the start, only where a bypass exists (`openOrthoCount ≥ 3`), and `ensureTrapsAvoidable` demotes any trap bridging to an otherwise-unreachable tile, so **every walkable tile is reachable without stepping on one**.
- **Every structural wing is GUARANTEED to connect** (`connectWing`, run after all wings are carved). A wing is a rectangle joined to the map by an artery, and that artery is fragile three ways: it's drawn BEFORE the wing's own hazards scatter, so a water clump can cut it; on an organic base it can dead-end in a one-tile pocket; and every wing used to stamp the same rectangle (right edge, vertically centred), so a second wing destroyed the first — the Mire's temple landed directly on its reed maze. In each case `sealUnreachable` then walls the wing away and the region stays TAGGED with no walkable tile, so the level silently loses a third of its content. `connectWing` checks whether the wing touches the largest floor mass and digs an L-corridor if it doesn't; wings are also anchored by ORDINAL now (right / left / top / bottom), with ordinal 0 keeping the original anchor so single-wing levels generate unchanged. Soak check `7` pins it, and it reddens hard without the fix: 33/60 seeds on the Mire, 9/60 on the Iron Gate.
  - **"Joined" means the wing's BULK, not one of its tiles — and getting that wrong is invisible by construction.** `connectWing` returned as soon as ANY region-tagged floor tile touched the main mass. A room-based layout (`hall`, `rogue`) leaves margin tiles between its outer wall and the wing rectangle, and those are region-tagged floor too, so a single margin sliver short-circuited the whole function while the hall's interior stayed marooned. It is the same error as an artery stopping at the first floor tile it meets, one level up: the wing WAS joined, just not the part anybody walks in. It now floods the wing's own floor into components, takes the largest, and tests and digs from THAT.
  - Measured on the Mire's temple (`sanctum`/`hall` — the level's destination, pinned by `goalHere`): **6.5% of seeds kept 1-2 walkable tiles out of a typical ~290**, and its reed maze another 12.5%; the Sunken Crypt's catacomb 3%. After: 0% on all six wings, with the Mire's temple p10 rising 51 → 237 tiles and the reed maze 16 → 163.
  - **Why nothing caught it, and the lesson for any future region check:** `sealUnreachable` turns the marooned floor into WALL, so after generation there is no unreachable floor left to find — only a wing that looks small. Both existing tests (`floor === 0`, `reachable === 0`) therefore passed on a wing reduced to a sliver. The detectable signal is floor measured against the region's own TAGGED footprint, which survives the walling: healthy wings bottom out at 11% (the Mire's eroded reed maze), the bug read 0.1-0.3%, and soak check `7` now fails under 5%. Reverting the fix reddens 27/200 Mire seeds and 6/200 Crypt seeds.
  - **The visible symptom was somewhere else entirely**, which is worth remembering: it surfaced as a _weird exit placement_. `goalHere` pins the exit inside the region, so when the region was a sliver the exit had nowhere to go but the one surviving cell — a one-tile hole punched through a wall with open water behind it, on 22% of Mire seeds.
- **Measure a wing by REGION ID, never by biome.** This is how the bug hid for so long. A wing whose biome equals its level's base — the reed maze in a marsh, the crypt maze in a crypt — counts base tiles when measured by biome and reads as a flawless 100%. Measured honestly, the Mire's maze was severed on **40%** of seeds and the Crypt's on 12%, long before any recent work. I drew the wrong conclusion twice from the biome-based number ("existing wings are fine, so this isn't a general bug") before noticing.
- **A wing's bridge must reach REAL space, not the first floor tile it meets.** `carveSubBiomeWing` tunnels an artery leftward out of the wing and stops when it hits floor. Stopping at the _first_ floor tile is wrong on an organic base: a `cellular` marsh is full of one-tile pockets, so the artery joined the wing to a dead pocket and `sealUnreachable` then walled BOTH away — the region stayed tagged but had zero walkable tiles. Measured on the Mire's temple wing: **severed on 35% of seeds**. It stayed hidden for so long because every wing before it used `maze` or `cellular`, which fill their rectangle densely and overlap real floor by luck; the failure only appears with a room-based layout (`hall`, `rogue`) that leaves wall margins. The stop condition now also requires an open neighbourhood, which a pocket fails and a cavern passes immediately — verified the existing wings are bit-identical (Pit 100%, reed maze 100%, crypt maze 100%). **A severed wing is invisible without a check**: nothing in the suites looked at whether a region still had floor, so the level simply lost a third of its content on those seeds and nobody would have known.
- **No teasing dead pockets** — `sealUnreachable` flood-fills from the player (cracked walls and shut doors count as passable) and walls off anything it can't reach.
- Both run AFTER hazard/region carving, so sub-biomes and vaults can't break them.

### Terrain & hazards

- **Impassable**: `water` (Rimewalk freezes it to a permanent `ice` bridge; floods can fill it) and `chasm` (a void — only Levitation crosses, no ice bridge).
- **`oil`** slicks (`LevelConfig.oilCount`) catch fire and the blaze races one tile/turn across them, burning each to bare floor.
- **`bramble`** thickets (drawn `&` — deliberately NOT `‡`, the altar's glyph: a hazard and a boon must never share one, which `/style`'s collision report exists to catch) **snag** whoever pushes through, refreshing a short bleed (`CONFIG.brambleBleedDuration`, `brambleSnag`; entered via `movePlayer`, alongside `springTrap` for traps); Levitation floats over them. They're **flammable**, so burning a path clears the thicket (`igniteTile`/`tickFires`) — a firebomb or the Pyromancer's Scorch shines here.
- **`sporeVent`** fumaroles (`LevelConfig.sporeVentCount`; placed as isolated singletons ≥`SPORE_VENT_GAP` apart by `placeSporeVents`, so clouds never merge into one lethal fog) seep a lingering **poison haze** (`GameState.gasTiles`, JSON-safe). `tickGas` re-emits the CORE (vent + orthogonal neighbors) every turn at `gas.ventLife`, and flares the diagonal ring every `gas.breathPeriod` at the deliberately shorter `gas.breathLife` — a bounded _pulsing_ pocket, not a spreading tide. Each vent also runs a **duty cycle** (`gas.ventActive` of every `gas.ventPeriod` turns, phase-offset by its own tile index so a level's vents don't puff in unison), so the haze clears COMPLETELY and later returns — roughly 6 turns hazy, 6 clear. A permanently-hazy pocket is static terrain you route around once and forget; an intermittent one is a timing decision (wait for clear air, or push through and take the poison), and it stays fair because the `○` vent tile stays visible even while the air is clear, and because the vent **telegraphs**: on the single turn before it seeps it enters `priming` and the renderer swells + brightens it (`◉`, `SPORE_VENT_PRIMING_*` in `tiles.ts`), so an attentive player can step out of the footprint — the same contract as the lich's barrage marking its tiles a turn early. The duty-cycle arithmetic lives in ONE place, the pure `ventState` in `core/gas.ts`, shared by `tickGas` and the renderer: duplicating it would let the warning drift out of step with the thing it warns about, which is worse than no warning. Test `[47]` asserts every priming turn is immediately followed by a seeping one, that each cycle has exactly one warning turn, and that the warning differs from idle in BOTH glyph and color (a color-only tell on a small glyph is the mistake the haze itself once made). **The two lifetimes must differ**: when the ring shared `ventLife` it was refreshed on precisely the turn it would expire, so the cloud swelled once and then sat frozen at full extent forever — and because the renderer alternates the glyph (`∴`/`°`) off the wall clock it still _looked_ alive, which is what hid it. Test `[47]` now asserts the extent actually oscillates; "bounded" alone was satisfied by the frozen cloud; `CONFIG.gas.poisonDuration` sets the affliction. **Levitation gives NO protection** (it's airborne); go around or cure with an Antidote. Deterministic (no RNG).
- **`crackedWall`** (`crackedWallCount`) — placed only where it separates two open spaces (so it's a real shortcut). Opens three ways: an explosion (firebomb/Ruin), a **knockback** weapon slamming a monster through it, or melee-bashing it down over `CONFIG.crackedWallToughness` bumps (`GameState.crackedWallHits`).
- **Doors** (`door` shut = blocks move + sight; `doorOpen` = walkable + see-through; `LevelConfig.doorCount`). Generated OPEN on 1-wide chokepoints (`placeDoors`) so guarantees are unaffected. Bump to open; `[c]` (`closeDoor` action → `closePlayerDoor`) pulls one shut to break LOS, wall off pursuers, or dam a flood. Most monsters reroute (door-aware `stepToward`); `MonsterDef.opensDoors` foes (goblin, Gate Warden, Herald, Malachar) spend a turn forcing it.
- **`forage`** heal tiles (`LevelConfig.forageCount`) tucked in nooks off the beeline (`placeForage`): step on one for a little HP (floats a green `+N` via the `heal` `GameEvent`) (`forageStyle(biome)` — outdoor berries +1, arcane motes +2; generous outdoors, sparse in the castle, none in the throne), then it's spent. Skipped at full HP.
- **Knockback cuts both ways.** `ItemDef.knockback` (Flanged Mace) shoves a struck survivor back — into water/chasm is an instant kill (`isWalkable` gates the shove). `MonsterDef.knockback` foes (**Gargoyle Sentinel**) shove the PLAYER; into a chasm/water while not levitating is a **fall**, a lost life (`resolveMonsterAttack`). Telegraphed by the visible void plus a **brink warning** (`senseBrink`), and your own steps into a chasm are always refused — so it's positioning skill, never a surprise.
- **Light tracks HABITATION, and a freestanding structure is not inhabited.** Wall sconces are placed render-side on `SCONCE_BIOMES` walls, but a hut tags its region `dungeon` purely to borrow that biome's plain `#` wall and lack of weather — and `dungeon` is a sconce biome, so every cottage in the Blackwood and wayshrine in the Mire burned a bracket. On those levels the structure walls were the **only** eligible walls on the map, so 100% of the budget landed on them (42/42, 39/39 and 11/11 candidate walls on the Blackwood, Mire and Frostspine). `GameMap.structureRegions` is what lets the renderer tell "tagged `dungeon` for its glyph" apart from "actually a dungeon"; those three levels now declare `sconces: 0` and are lit by their own daylight instead. Test `[68]` pins the tagging.
- **`SKYLIGHT` is what you see by with NO light of your own** (`unaidedSight`, resolved at the player's tile — walking through a gate takes the sky away). A missing entry silently means the pitch-dark floor of `CONFIG.unlitSight`, which is why the Iron Gate's **graveyard** — its base biome, 74% of the map, and where you start on 93% of seeds — gave 3 tiles while the ash-field beside it gave 7: stepping off the graves onto burned ground made you see _further_. `graveyard` is 9 and `sanctum` 6 (its own ambient is literally "daylight through a broken roof"). The `/style` biome grid now prints the value per biome, so an omission is visible rather than inferred. **A level may override the sky its biome implies** (`LevelConfig.skylight`), which exists because a biome can lie about whether you are outdoors: the **Ramparts** is an exposed wall-walk whose biome is `castle`, so it inherited the sealed-interior floor and gave **3 tiles** on an open battlement — while its own icy stretch, a `mountain` sub-region, gave **11**. Four-fold, between adjacent tiles of the same wall. The override replaces the base value and **caps every sub-region**, because a level has one sky (snow throws daylight back only if there is daylight). Ramparts is `4` — a stormy night: dim enough that a torch still buys +44 tiles on the one level with real fuel pressure, open enough that the wall stops reading as a corridor. Levels wanting the indoor/outdoor transition (the Iron Gate's graveyard → gatehouse) simply omit it. Test `[70]` pins the cap.
- **Torch fuel** — managed light; sensed traps live in `GameState.knownTraps`; a guttering torch dims and warms as it dies.
  - **Light must stay OBTAINABLE, and that is now an invariant** (test `[73]`). Since sight is light-gated, running dry drops you to `CONFIG.unlitSight` of 3 tiles indoors — so a stretch of levels with no way to buy or find a light source is a dead end, not a difficulty spike. It was quietly violated: shop tiers **7, 8 and 9 stocked no light at all** and no back-half level dropped one, so from the Sunken Crypt onward a run could not obtain light by ANY means — across the four darkest levels in the game, with only ~1.1 findable torches in a whole run. Tiers 7/8/9 now stock a torch, a lantern (before the storm-lashed Ramparts, where a bare flame is the wrong tool) and a torch; four back-half drop tables carry one. Findable torches **1.1 → 3.3 per run**. `[73]` asserts no stretch longer than 2 levels without either channel, and prints the offending levels when it fails.

### Inventory — one weapon, one suit

`equipWeapon`/`equipArmor` **return the piece they displaced** rather than stowing it, and the caller decides where it goes: the floor at your feet in play (`dropAtFeet`), a trade-in credit at a shop counter. Nothing is ever destroyed. The bag used to absorb it, which quietly made it a gear warehouse — a run turns up ~11 pieces worth **178g** of sell value against a ~190g purse, so most of an "inventory" was spare kit you were never going to wear.

- **Gear is no longer auto-taken; it is a step-onto POI** (`mode: "gear"` → `GearModal`, the same flow as altars and lore props — offered AFTER the move resolves, so it never blocks a route and declining walks you over it). The old rule equipped on a bare `(def.power ?? 0) > p.weaponPower`, and **power is not the only axis**: that silently traded a Frostbrand's chill, or a mace's knockback, for one point of axe. Merely lossy while the displaced piece went to your bag; irreversible once it lands on the floor. So the prompt is what makes the swap safe, and it shows the comparison plus the traits (`onHit`, `knockback`, `ranged`) that the game surfaces nowhere else.
- **QUEST gear stays automatic.** The Sunblade is a `weapon` carrying `questTag`, and it IS the Sunken Crypt's objective — a declinable prompt would let a player refuse their own goal.
- **Buying gear trades in.** `giveItem` returns the displaced piece and the store credits `sellPrice`; there is no floor to drop it on at a counter. It also no longer second-guesses the purchase — you chose to buy it.
- A bag can still HOLD gear (an older save, the dev jump), so `equipFromBag` stays reachable and drops the displaced piece at your feet.

### Status effects, combat & AI

- **Status system** (`src/game/core/status.ts`, `PlayerState.effects`, ticked by `tickEffects`) — a timed-effect bag on player AND monsters: poison/bleed/burn (armor-ignoring DoT) + chill (a brief freeze; monsters skip their turn). Monsters afflict via `MonsterDef.inflicts`, the player back via weapon `ItemDef.onHit` (Frostbrand chills) and firebombs. Cured by Antidote (`cleanse`); DoT ticks route through the normal death path and float a status-tinted number.
- **Potions** — Warding (halves damage), Might (weapon boost), Vial of Ruin (self-AoE), Draught of Seeing.
- **Terrain-defying draughts** (each an `effects` key) — **Levitation** (`levitate` — glide over water/chasm, float over traps unsprung; lapsing over water scrambles you to shore via `landFromLevitation`), **Emberstep** (`emberstep` — suppresses fire searing), **Rimewalk** (`frostwalk` — freezes crossed water to permanent `ice` — enemies can use it too), **Shadowcloak** (`shadow` — caps detection at `CONFIG.shadowSightRadius`), **Phial of Blinking** (`blink`; `beginBlinkTargeting` opens the cursor, `blinkTo` → `resolvePlayerBlink`, teleport within `CONFIG.blinkRange`).
- **Fire** — firebombs thrown via the `targeting` cursor (`throwAt`) scatter lingering `GameState.fireTiles` that sear whoever stands in them and burn down over a few turns, leaving scorch decals.
- **Status RESISTANCE** (`MonsterDef.resist`, per `StatusKind`; 1/omitted = normal, 0 = immune) scales both the chance to land and the duration, so one number covers "shrugs it off" and "shakes it off faster". It exists because **chill makes a monster forfeit its turn**, which means a weapon that re-applies it faster than it expires doesn't damage a boss, it deletes one: the Frostbrand (`chance: 0.5, duration: 3`) refreshes the freeze while the target is _still frozen_, and **Gorm, the Frost Troll spent 55% of the fight unable to act** — the weaker Frostbrand (power 7) left you on 22 HP where the stronger War Axe (power 8) left 6. `resist: { chill: 0.5 }` takes that to 16%. Deliberately NOT immunity: at 0.25 or below the chill never lands at all, and a status that silently never applies reads as a broken weapon rather than a resisted one. Any hard-CC status wants this check — `inflicts`/`onHit` is the first dial to look at on a trivialised fight, not the last (same lesson as the wraith's bleed).
- **Elites** (`MonsterInstance.elite`, table in `ELITE`; rolled per `LevelConfig.eliteChance`, never on bosses) — **brute** (tankier, hits harder), **swift** (acts twice/turn), **volatile** (bursts on death for `CONFIG.eliteExplodeDamage`). Double coins, guaranteed loot, champion tint.
- **Stealth via light** — detection is capped at `min(sightRadius, player.lightRadius, shadow ? CONFIG.shadowSightRadius : ∞)`, so dousing your torch lets you approach unseen; striking a still-`idle` chaser is a **sneak attack** (`CONFIG.sneakMultiplier`).
- **Monsters aren't omniscient** (`actMonster`) — when they lose you they hunt your **last-seen tile** (`MonsterInstance.lastSeen`) and after `CONFIG.loseInterestTurns` give up back to `idle` (`lostTurns`), so breaking LOS and waiting genuinely shakes a pursuer. Bosses never lose interest.
- **Ranged weapons** (`ItemDef.ranged = {range, ammoId}`) — with a bow equipped, bump = point-blank shot and `[f]` opens the cursor (`kind:"ranged"`) to loose at a tile in range + LOS (`shootAt`); each shot spends an `am_arrow`, and running out drops you to a feeble 1-dmg jab.
- **Monster loot** (`MonsterDef.loot` = chance + weighted table) drops on the corpse tile; bosses guaranteed.

### POIs & exploration

- **Altars** (`GameState.altars`, `LevelConfig.altarCount`, `src/game/core/altar.ts`) sit on **walkable** floor and never block a route — the offer opens AFTER you step on, so declining just walks you past. One pre-rolled bargain each (vigor: gold→+maxHP; **warblood**: −maxHP→permanent `PlayerState.weaponBonus`; hoard: HP→potions+gold); `applyAltar` is pure.
- **Lore props** (`GameState.lore`, `LevelConfig.loreCount`, text in `src/content/lore.ts`) — walkable `¶` glyphs placed by `placeLore` into NOOKS off the beeline (`openOrthoCount ≤ 2`). Step on an unread one to open a read-only `lore` mode (`LoreModal`; marks it `read` so it won’t reopen); no cost, no boon — the payoff is STORY. Each fragment is drawn from the pool of **the prop's own REGION**, not the level's base biome, so it speaks for where it lies and sub-region-only pools (`grove`/`undercity`/`cavern`/`ashen`) actually reach the player. Corollary enforced by test `[0]`: a fragment must not name a place its biome can appear OUTSIDE of. Flood levels protect lore tiles so an inscription never drowns unreadable.
- **Lore can give ADVICE, and advice must not lie** (`LoreEntry.claims`, test `[75]`). A fragment telling you how to fight something is only worth reading if it is right, and prose drifts silently: "frost cannot touch it" holds exactly as long as `MonsterDef.resist` says so, and changing that dial would leave the game lying to the player forever with nothing to catch it. Declaring the claim (`{ monsterId, resists }`) makes it checkable against `MONSTERS`, and also pins it somewhere the knowledge is USABLE — a warning about the troll is worthless on a level the troll never appears on, so the check requires the pinned level to spawn it, target it, or cage it as a vault guardian. Seven so far: a hunter's cairn warning that Gorm shrugs off cold (otherwise invisible — the only way to learn it is to waste a Frostbrand on him), and a VAULT hint on each of the six levels that hides one. That completeness is itself checked — a vault nobody hints at is a room you find by luck, and the clue system would otherwise be decoration on whichever levels happened to get written first.
  - **A vault hint never claims a position**, because the vault is placed per seed and a directional hint would be wrong most of the time. What it claims is authored and stable: the GATE (`{ gate, guarded }`), which is the actionable half — bashing through a cracked wall and hunting a shut door are different searches — plus whether something is caged in with the hoard. The check holds all three against `LevelConfig.secretVault`, so naming the wrong gate, inventing a guardian, or pointing at a level whose vault was removed all redden.
  - **`placeLore` seeds exactly ONE clue first**, and that is what makes advice worth writing. Drawn purely at random it barely arrived: the Great Hall's strongroom hint reached the player on **21%** of runs, the Frostspine's on ~40%. Seeding one takes that to **81-100%** while leaving room for flavour — at `loreCount` 2 the Frostspine would otherwise spend both props on advice and never show its atmosphere. Pinned at a 70% floor, which sits clear of the 21-40% "before" and the 81-100% "after". Per-vault reach now runs 64-99%; the Frostspine sits lowest only because it carries TWO clues that compete for the one seeded slot, so it still delivers _some_ advice on every run.
  - **A clue can never be a GATE.** Props are drawn at random from a pool larger than `loreCount`, so a given fragment reaches you on **22-89%** of runs by level (Mire 83-89%, Frostspine ~67% before this addition and 48% after, Iron Gate ~48%, Great Hall ~27%, Sunken Crypt ~25%). Requiring one would soft-lock most runs. Knowing is an advantage; not knowing costs a harder fight, never the run. A `LoreEntry.always` seeding flag would be the way to make a specific clue reliable if a level ever needs one.
- **A pool is keyed by BIOME, but two levels can share a biome and not be the same PLACE** (`LoreEntry.levels`). The Great Hall's new `crypt` undercroft and `ashen` collapsed nave exposed this: every `crypt` fragment had been written for the Sunken Crypt and narrated a flood ("toward the rising water", "when the crypt drowns") in a dry cellar two levels early, one of them naming the **Sunblade** before the game introduces it; both `ashen` fragments described the siege outside the gate — a slagged ram, burned fields — while sitting inside a cathedral. A fragment tied to a place now declares it, and the biome-general ones stay unpinned and serve both. Three guards, because every failure here is silent: a typo in a pin deletes a fragment from the game, a pin naming a level that lacks the biome is dead content, and — the subtle one — **the pool check has to be keyed by (level, biome) against the FILTERED pool**, since pinning every `crypt` fragment to the Sunken Crypt leaves `LORE_POOLS.crypt` six entries deep while the Great Hall's undercroft can draw none of them, and `placeLore` then just puts the props elsewhere on the level and loses the region's story with no shortfall to notice.
- **Ambient wildlife** (`MonsterBehavior "ambient"`, placed via `LevelConfig.ambient` OUTSIDE the combat `monsterBudget`) — they **drift** and **flee** within their shy radius (`driftAmbient`), never attack, and **disperse** harmlessly when bumped (no combat, coins, loot, or kill credit). Kept rare so they read as a treat: the **Will-o'-Wisp** (`wisp`, Blackwood — also a drifting light source via the opt-in `MonsterDef.glow`), **Carrion Ravens** (`raven`, Ramparts), **Mire Frogs** (`marsh_frog`), a **Snow Hare** (`snow_hare`, Frostspine). New species are pure data — an `ambient` `MonsterDef` + a `LevelConfig.ambient` entry.

### Classes, abilities & run modifiers

- **Classes** (`src/content/classes.ts`; picked on the `classSelect` screen, stored as `PlayerState.classId`) — **Warrior** (Short Sword + Leather, 26 HP, `damageReduction` 1), **Rogue** (Dagger, 16 HP, `sneakMultiplier` 3 + `critChance` 0.2), **Pyromancer** (Bow + arrows + firebombs, `bombPower` +6). Passives read at their sites: DR through the shared `mitigate` choke point (enemy melee + bolts, not hazards), sneak/crit in `resolvePlayerAttack`, bomb bonus in `detonateAt`. `"wanderer"` is the neutral baseline for tests/legacy saves. Each has a glyph badge (`ClassDef.glyph` — ⚔ / † / ✷).
- **Active abilities** (`ClassDef.ability`, `[q]`, on `PlayerState.abilityCooldown`; routed through `useAbility`, aimed via `triggerAbility`) — Warrior **Cleave** (hits every adjacent monster), Rogue **Dash** (leap 3, landing like a blink), Pyromancer **Scorch** (a widening cone of `igniteTile`). Directional ones open a lightweight aim where the **next movement key IS the direction**.
- **Run modifiers** (`src/content/mutators.ts`) — opt-in seeded trials picked after class select (a `mutators` UI mode + `MutatorSelect` screen; `store.selectedMutators` → `beginRun`). `applyLevelMutators` runs in `beginLevel` BEFORE generation (so all generator guarantees still hold); `applyPlayerMutators` does run-start tweaks. Active ids live on `GameState.mutators`, roundtrip in the save, and raise the end score (`mutatorScoreMult`, shown on `RunStats` alongside `store.runResult`). Set: Dark Deepens / Restless Dead / Treacherous / Forsaken / Champions / Glass.
  - **A trial may only touch GENERATION-TIME config fields** (`baseLightRadius`, `monsterBudget`, `itemDropCount`, `eliteChance`, hazard/POI counts). `applyLevelMutators` runs at exactly ONE site — `beginLevel` — while ~30 other sites re-read the RAW `LEVELS[...]` entry (`goals.ts`, `levelParBonus`, `awardCoins`, `tickFlood`, the HUD, the renderer). Mutating `turnLimit`/`coinRichness`/`goal`/`flood` is therefore a **silent no-op you'd never see fail**; test `[40]` locks the touched-key set so a trial reaching for one reddens instead. The ONE mutator-aware runtime reader is the **siege** (`maybeReinforce`/`spawnWave` via `effectiveConfig`), which spawns monsters mid-level and so must honor the mutated `monsterBudget` + `eliteChance`. To make another runtime field respond to trials, route that site through `effectiveConfig` too — don't just widen the whitelist.
  - `champions`' `max(0.3, …)` **floor** is what makes it work at all on the three levels declaring no `eliteChance` (a bare `× 2` would leave the Pit/Blackwood/Throne untouched). `forsaken`'s `× 0.6` **compounds** with the global `CONFIG.lootScale` (0.67) applied later in `generate.ts`, so the count actually generated is ~0.40× of authored.

### The boss fight

Malachar (`behavior: "bossLich"`, tuned in `CONFIG.lich`) fights in three HP-gated **phases** (>2/3, >1/3, ≤1/3) that escalate ability frequency and scale: he hurls bolts, **summons** capped clusters of risen dead, rains a **telegraphed dark-fire barrage** (`GameState.barrage` marks tiles one turn, `resolveBarrage` detonates at the top of the next monster phase — one turn to step clear), and **blinks away** (`lichTeleport`) when cornered from phase 2 on.

### Sub-biome regions

`GameMap.region`/`regionBiome`/`regionPalette` tag each tile with a region id (0 = the level's own biome; JSON-safe `number[]`, so they roundtrip in the save). `carveSubBiome` shapes an optional `LevelConfig.subBiomes[]` — an ARRAY, so a level can host several regions (ids 1, 2, …) — two ways per entry:

- an organic **Simplex-noise blob** (`carveSubBiomeBlob`) — cosmetic, never touches tiles;
- a rectangular **wing whose _structure_ is a secondary generator** (`carveSubBiomeWing` + `spec.layout`, e.g. a `maze` catacomb) — bridged to the main map by cleared cross-arteries so a perfect maze stays navigable.

**A NATURAL wing must look grown, not built** (`SubBiomeSpec.organic`, `organicGrid`). `genGrid("maze")` is a perfect rectilinear lattice — correct for the Sunken Crypt's bone catacombs, which are masonry, and wrong for the Mire's reed thicket, where the same generator put a hedge maze in a bog. That made the level's one NATURAL feature the only thing on it generated as architecture, beside a temple and four wayshrines whose straight walls are deliberate — which is exactly what reads as "sometimes organic, sometimes not." It is **opt-in**, because rectilinear is the point for every other wing (all six structural wings: `cellular` cavern, two `maze`, `hall`, two `rogue` — and the reed maze was the only natural one). Two operations, and it needs BOTH:

- the lattice is cut at **half resolution and doubled**, which is what kills the uniform one-tile pitch. Erosion alone cannot: thinning a 1-thick wall only makes it gappy, so the lattice survives as a dotted lattice. Doubling also makes the erosion **safe** — channels are 2 tiles wide, so removing wall can never sever one and the pass stays monotone (floor only grows), so no connectivity guarantee can break.
- the walls are then **eroded** — any nub with 3+ open neighbours goes (this removes the right angles and rounds the wing's own rectangular outline into the base biome), plus **two octaves** of noise punch wandering channels. The fine octave is not decoration: doubling makes each row an exact copy of its pair, and one low-frequency field barely changes over two tiles, so the pair erodes identically and the result carries visible 2-row banding — trading the old lattice for a subtler one.

Measured on the reed wing: wall share 78% → 57%, pure-straight wall tiles 34 → 7 per seed, median straight run 9 → 7, and the level's walkable area moves only +3% so no rebalancing follows. **The erosion threshold is a look dial with a floor and a ceiling**: at 0.30 the thicket thins to 47% wall and stops being something to get lost in; at 0.52 it fills to 66% and becomes a solid blob with no channels. Test `[67]` pins both ends of the rule — the reeds must read grown AND the catacombs must stay masonry — via the share of a region's wall tiles that are pure-straight interior (catacomb 47%, reeds 6%). That metric is deliberately **not** a run-length or right-angle count: both invert at high density, since a thick bank has perpendicular neighbours and so scores as "not straight" for the wrong reason. `organic` also **throws on a room-based layout** rather than crashing inside rot.js — `ROT.Map.Rogue` dies in `_createCorridors` when asked for a half-resolution grid.

`scatterRegionHazards` then fills the region with a **hazard kit** (`spec.hazards[]`; omit to inherit a per-biome default from `BIOME_HAZARDS`) as scattered specks, or as flood-grown contiguous **pockets** via `clumps`. All of it runs BEFORE the connectivity pass, so the generation guarantees still hold (a severed pocket is just abandoned).

The renderer resolves biome/palette **per region** — `terrainGlyph`/`terrainColor`, the lighting ambient in `litVis`, and `paintAtmosphere` (which gates each biome's weather to its own region's cells).

**Two placement options make a level a JOURNEY rather than a field with an exit somewhere in it** — both narrative, not difficulty:

- `SubBiomeSpec.noStart` — a region you may never begin in. Narrative, not difficulty: several levels are a journey INTO somewhere, and spawning past the threshold spends the arc before it starts. Marked per region for the level's **destination** (the Mire's temple), a **discovery** it exists to reveal (the Great Hall's undercroft — first sight of what Blackhall keeps underground), a **labyrinth** that is somewhere you go into rather than wake in (the Mire's reeds, the crypt's catacombs), a **self-lit lure** meant to draw you from outside (the Pit's glowcap hollows, the Mire's grove), or simply hostile ground (the Blackwood's briar, whose thorns snag on entry). Still deliberately a blocklist rather than "start in region 0" — the Iron Gate reads correctly on the graves OR out on the burned siege ground, the Blackwood in woods, bog or glade — so what stays allowed is as considered as what doesn't.
  - **It is matched by REGION ID, and the biome-keyed version it replaced could not express the cases that mattered most.** A sub-region often shares its level's base biome: the Mire's reed maze is `marsh`, the Sunken Crypt's catacomb is `crypt`, and the Blackwood's glade and briar are BOTH `forest`. Blocking by biome would have taken the base region with it, or been unable to tell two sub-regions apart — the same biome-vs-region-id trap that hid the severed-wing bug. Measured across all ten levels: the Sunken Crypt began in its base region on only **40%** of seeds (27% deep in the catacombs, 25% in the flooded underworks the level's own water comes from), the Pit **50%** (the glowcap cavern is self-lit, inverting the lesson level 1 exists to teach), the Great Hall **75%**. All three now read 100%; the Iron Gate, Blackwood, Mire, Frostspine and Ramparts keep their deliberate alternates.
- **The exit is chosen for SHAPE as well as distance** (`farthestSafeCell`). It sorted purely by distance and returned the first cell whose removal gated nothing — and a one-tile hole in a wall with water behind it scores perfectly on both: it is genuinely at the region's extremity, and nothing is behind it to gate. `farthestCell` had long since learned this for quest items ("a destination, not a cul-de-sac": take everything within `FAR_SLACK` of the maximum, prefer the most open); the exit never got it. It now walks the same far-end band preferring ≥3 open orthogonal neighbours, then ≥2, then falls back to the old rule so a cramped region still gets an exit. Independently worth it: with the `connectWing` fix alone the Mire still wedged the exit on 13% of seeds and the Pit on 7%; with both, 0% and 2%.

- **A destination region can be carved next to the start** (`CONFIG.minStartToExit`, applied at the single `pushStartAwayFrom` choke point). `goalHere` takes the farthest cell WITHIN a region, which is only far if the region is — so ~2% of Mire seeds put the exit within 20 steps and the worst put it at 3. Corrected by moving the START, not the goal: the goal stays inside the region that makes it the destination, and the start is re-drawn from the same pool, so `noStart` and the component anchor still hold. A random eligible cell, not the farthest — on a triggering seed the farthest is always the opposite corner, which swaps a rare short run for a predictable one. The floor only touches the tail: the Mire's median run length is unchanged (~71) while the minimum goes 3 → 21 over 1000 seeds. **The 20-tile floor this level was once documented as already having was never true** — it was measured on too few seeds to see the tail, the same granularity lesson as the 12-seed win rates.
- `SubBiomeSpec.goalHere` — the region the level's OBJECTIVE belongs in, so it becomes the destination instead of a side room you may never enter. Covers all three single-objective goals (the `reachLocation` exit, the `killTarget` boss, the `findItem` item), because the failure is the same in each: the Gate Warden — whose entire identity is holding the gatehouse — stood out on the open graves on **60%** of seeds, wasting the one built interior on the level. Region-id keyed, replacing the biome-keyed `exitInBiome` for the same reason `noStart` is: a biome-keyed flag cannot name one of two regions sharing a biome, and silently means "any of them".
  - **Constraining WHERE the goal sits loosens how FAR it is** — necessarily, since the far end of one region is nearer than the far end of the map. Pinning the Warden inside the gatehouse took the Iron Gate's shortest run from 43 steps to **17**. `CONFIG.minStartToExit` now applies to every single-objective goal, not just the exit, via one `pushStartAwayFrom` choke point — and it is measured on a DEEPER sweep (150 seeds on each level that constrains its goal), because the 40-seed sweep caught none of that tail.
- **The APPROACH is a third distance, and it is the one an outside→inside level is actually about** (`CONFIG.minStartToGoalRegion`, 18). `minStartToExit` measures the goal TILE and can be satisfied entirely indoors: you may begin 30 steps from the Gate Warden but **three steps from the gatehouse door**, walk in, and cross the interior — skipping the outdoor half the level exists for. Measured before the floor: **13% of Iron Gate seeds put the building within 10 steps** (19% within 15), 9%/19% on the Mire, against a median approach of 35. Enforced by FILTERING the start pool rather than moving the start afterwards — the region is already carved when the start is picked, so one multi-source BFS out from it gives the true walking distance. After: minimum approach 18 on both, zero seeds under 15, and the median rose (35→40, 36→42) because the pool now favours farther starts.
- **Used together they need care, and they usually SHOULD be used together.** Both ends of a journey in one region is the worst version of this: the Mire's temple spawn meant starting essentially at the exit. The Iron Gate is the same shape read forwards — `goalHere` puts the Warden in the gatehouse, `noStart` keeps you outside the walls, and together they make the level "fight your way in". Whenever you set one, ask immediately about the other. Measured after: goal in the intended region 100%, never starting in it, min run 33 / median 76 (Iron Gate) and 30 / 69 (Mire).

**Adding a biome** is data: extend the `Biome` union, fill its tables (lighting ambient, music mood, title gradient, lore pool, and optionally atmosphere / glyphs / `BIOME_HAZARDS`), then reference it from a `subBiomes[]` entry. Sub-region-only biomes (`cavern`, `ashen`, `grove`, `undercity`, `sanctum`) never appear as a level's base biome; `graveyard` does (the Iron Gate).

### Map generators

New `GeneratorKind`s — `rogue`, `maze` (`DividedMaze`), plus custom `hall` (a cathedral nave, `genHall`), `rampart` (a linear wall-walk, `genRampart`) and `gallery` (a processional statue gallery, `genGallery`) join `digger`/`uniform`/`cellular` behind the shared `genGrid` helper. All are whole-level-capable and usable as wing layouts.

### Secret vaults & lairs

`LevelConfig.secretVault` (`placeSecretVault`) carves a fully-walled room of loot reachable ONLY through a single **gate** — a **cracked wall** to blast/bash (default) or a shut **door** to open. Carved AFTER normal placement so it's a separate floor component (spawns never leak in), and it survives `sealUnreachable` because both gate types count as passable in that flood (`isOpenTile`).

- **Sealed means sealed to SIGHT too.** The enclosure check covers all 8 neighbors, because FOV runs at `topology: 8` — one transparent diagonal corner used to reveal the whole vault through the "sealed" wall. Guarded by test `[56]`.
- An optional **`guardian`** (a monsterId) seals a monster in with the hoard, turning free loot into a risk/reward **lair**. Placed on the far side from the gate so breaking in doesn't drop you onto it; it can't path out because the gate isn't walkable until you open it, so a `guardChase` beast just waits, dormant.

### Freestanding structures

`LevelConfig.structures[]` (`placeStructures`) is the OUTDOOR counterpart: instead of digging into existing wall, it stamps visible **wall boxes** (floor interior + one shut door + loot) onto open clearings — a hut in the woods, a shrine in a field. It's an ARRAY, so several entries read as a **hamlet** (each re-scans for its own clearing, so they never overlap).

Stamped BEFORE the component pass (door-sealed interiors drop out of `largestFloorComponent`, so nothing spawns inside), and required to sit in an all-floor footprint + 1-tile margin on the **main reachable component** — never an isolated pocket, or `sealUnreachable` would wall the loot away. Because stamping huts can flip which component is "largest" on a fragmented map, structure levels anchor player+spawns to the SAME component the huts opened onto (`floorComponentFrom`), never merely the largest. The footprint gets its own cosmetic region (timber by default, overridable per structure via `spec.palette`) so the walls read as _built_; region is purely visual — tile TYPES still drive every mechanic.

### Per-level signature beats

Every level carries one:

- **The Pit** (56×34) — a `cellular` **cavern** wing holding several glowing **fungal hollows** (`glowcap` pockets to navigate toward) + a door-gated cell.
- **The Blackwood** (84×52) — a boggy marsh patch, a bright **glade**, a thorn-choked **briar**, drifting **will-o'-wisps**, and a ruined woodcutters' **hamlet** of five varied huts with the shards scattered among them.
- **The Mire** (72×46) — water channels, dry grassy **hummocks**, a reed-thicket `maze` wing (green `♠` labyrinth, `organic` — see below), a luminous **fungal grove** (`grove` — beautiful and poisonous), poison **spore vents**, and a lone mossy **wayshrine**.
- **The Frostspine** (72×46) — a `cellular` cave network choked with **crevasses**: frozen tarns (`water`, Rimewalk bridges them) AND bottomless **chasms** (`chasm`, Levitation only) — plus two **ice grottos**, a border **watchpost**, and a sealed **beast den** (a cracked-wall vault with a dormant Hoarfrost Bear over a Frostbrand — optional, so it's a risk you choose).
- **The Iron Gate** (66×42) — a `rogue` **gatehouse** of connected guard chambers whose goal is the **Gate Warden** held at the FAR end (`killTarget` places it farthest-from-start, so you fight ACROSS the map; a cull goal used to end in the spawn corner, leaving it unseen), opening onto an **ashen wastes** region (falling grey ash, ember-glow, pooled `oil` a firebomb turns to an inferno).
- **The Great Hall** — a `hall` **cathedral**: a colonnaded nave with flanking side-chapels, a **collapsed nave** open to the sky (an `ashen` patch where the roof fell in — ash drifting down, and the one place in Blackhall with daylight), an **undercroft** below (a `crypt`-biome `rogue` warren, first sight of what the castle keeps underground) and a door-gated **strongroom**. It was the sparsest level in the game at **1.11 POIs per 100 walkable tiles** because `genHall` floored **74%** of the map where every other level runs 18-40%: the chapels used to floor their entire depth to the map border, separated by single-column dividers. They are now rooms of jittered depth cut into solid rock with masonry behind them, and ~1 bay in 5 is never built — floor share **74% → 42%**, density **1.11 → 1.92**, with no threat added and no change in size. **Halving the walkable area doubles monster density at a fixed count**, which is the same incomplete edit as growing a map and not scaling its population: the budget came 20 → 16 (measured at 40 seeds, 20 read 40% and 16 read 68%; a strictly area-proportional cut to ~10 reads 80%+ and makes a cathedral full of the dead feel empty).
- **The Sunken Crypt** (60×38) — a catacomb `maze` wing + a bioluminescent **fungal hollow** (glowcap islands that stay dry and lit as the black water rises) + the **Blackhall underworks** (`undercity` — green-stained sewer stone and flooded channels, which is _where the flood comes from_), all of it **flooding** as you hunt the Sunblade.
- **The Ramparts** (84×34) — a `rampart` **wall-walk**: an exposed battlement over a bottomless `chasm` beyond a crenellated parapet (shove the dead through the embrasures), inner **tower rooms** to fall back to, lashed by a lightning **storm** and glazed with **ice**.
- **The Antechamber** (66×40) — a `gallery` processional **statue gallery**: a wide promenade flanked by a double **colonnade** with side aisles behind the pillars (flank / break LOS), patrolled by gargoyle "**statues**" (`guardChase` — stone until you draw near). Varied per seed: **niches** are per-bay randomized (~30% solid, the rest 1–2 deep, ~40% of deep ones cracked-wall-gated with an offering cache), and ~half of seeds drop a **collapsed** section (an interior `chasm` pit with a ragged eroded outline, kept off the spine so you route around it — but a gargoyle can shove you in). Plus a door-gated **reliquary** and a cosmetic `throne` region — black marble veining up through the floor, the throne's own stone spreading backwards, carrying its rising-ember atmosphere (it was the last level with no sub-biome at all).
  - **A `gallery` map is one rectangular band, and over half of it was untouched rock** (a ~17-row hall in 40 rows). So the level's variety problem was never density — it measured a healthy 2.02 POIs/100 walkable tiles — it was that every seed had the same PLAN: you entered mid-corridor, walked a uniform hall, and the Herald made its stand in a stretch identical to every other stretch. `genGallery` now spends that dead rock: a **narthex and apse** swell both ends a few rows above and below the band (arrival reads as a vestibule, the far end as an arena worth fighting in), and 2–4 **flanking chambers** are cut into the rock beyond the outer wall, each reached by one passage off a side aisle, with count/size/side/position all jittered — a reason to leave the processional axis. Both only ever ADD floor, so neither can sever the hall.
  - **The extra area was measured to be balance-neutral**: at 40 seeds the old and new geometry both read **35%**, because the new rooms are off the spine and the bot never enters most of them — so `monsterBudget` stayed at 14 while the POI counts scaled with the ~16% more walkable floor. Worth knowing for the balance pass: that 35% is the **lowest non-boss win-rate in the game**, and it was already so before the rework. The 12-seed gate reads this level at 33%, which is inside its own noise — a repeat of the Iron Gate lesson.

- **The Throne** (44×28) — kept tight for the boss.

### Flooding set-piece

a level fills with water during play (`LevelConfig.flood` + `tickFlood`). `computeFloodPlan` marks a protected dry **spine** (shortest path start→objectives AND to every altar, dilated one tile) that never floods, so the goal — and each interactive altar — stays reachable throughout (verified even at full submersion; an unprotected altar would drown into water yet still render its `+`, stranded); everything else rises one ring every `interval` turns (from `startTurn`, capped at `maxSteps`) from **seeds spread across the whole near→far range** (count scaled to the floodable area) so the water wells up all over — including just off your route — rather than as one distant tide you never see; never floods onto an occupied tile. Water flows THROUGH an **open door** but a door pulled shut (`[c]`) **holds it back** — non-protected `doorOpen` tiles are floodable, a closed `door` is not (checked live in `tickFlood`), so shutting a door dams the flood down that corridor (player agency against getting boxed in). Water is impassable, so **Levitation** glides and **Rimewalk** freezes a path — the terrain-defying draughts become clutch. **It can never seal you in**: the dry spine only protects a player standing ON it, so before each rise `tickFlood` reserves a walkable escape route (`floodEscapeRoute`) from wherever you are back to permanently-dry ground — without it the ring floods every neighbor and maroons you on one tile, and since the turn limit is only a score target nothing ends the run (a softlock, not a hazard; skipped while levitating, guarded by test `[55]`). The flood is also tuned to be PRESENT rather than a late surprise — it starts early and spans the whole hunt, with a thinned garrison so the water is the antagonist, not the crowd. `GameState.floodable`/`floodSeeds`/`floodStep` (JSON-safe) drive + persist it. Live on the Sunken Crypt. **Set-pieces scale**: the Great Hall is a deliberately larger, airier map (grandeur, not a grind; since the turn limit is now just a par-for-score target, size no longer fights a turn-budget guard). Note `genHall` used to carve ~**77% floor** — by far the most open map, so a monster/item budget tuned for a normal level left it hollow. Its chapels are now real rooms cut into rock (**42%**), but the rule that produced that bug still holds: a `hall` level's counts are set against its WALKABLE area, not its dimensions (measure with the `medSeen` absolute-tile column + POIs-per-walkable-tile, never the raw share), and changing the generator's floor share is a change to density that the population has to follow.

## Workflow notes

- Do NOT auto-commit; the user commits. Verify with `tsc`/`build`/`test:core` + `npm run lint` and leave changes for the user to review on their own dev server (don't launch `npm run dev`). A pre-commit hook auto-formats (Prettier) and lint-gates staged files.
- **Page metadata & social images** live in `src/app/`: `layout.tsx` (title template, description, OpenGraph/Twitter, `viewport` for theme-colour) plus three generated images — `icon.tsx` (32px favicon), `apple-icon.tsx` (180px), `opengraph-image.tsx` (1200×630) — built with `ImageResponse` from `next/og`, so there are no binary image assets in the repo. Three things are load-bearing: each image route **must** `export const dynamic = "force-static"` or `next build` fails under `output: "export"` (metadata images compile to Route Handlers, and a static export has no server); the OG card is built from real game data (`LEVELS.length`, `SUBTITLE`, `tiles.ts` colours, `hud/palette.ts`) so it can't drift from the game; and Satori is **flexbox-only** and needs an explicit `display: flex` on any element with more than one child. Because only a proportional font is bundled (`Geist-Regular.ttf`), the glyph strip gets its monospace alignment from FIXED-WIDTH CELLS rather than the typeface — the same trick the game's renderer uses, and it avoids spending the 500KB `ImageResponse` budget on a font binary.
- **Set `NEXT_PUBLIC_SITE_URL` for production builds.** `metadataBase` needs an absolute origin and a static export can't know its own host; the fallback is `http://localhost:3000` on purpose, so a missing value shows up the first time someone pastes a link rather than silently pointing the OG tags at a domain we don't own.
- Bump `CONFIG.contentVersion` on any content/shape change so old saves retire cleanly (currently `"59"`).
