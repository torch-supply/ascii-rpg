# Ember of Dawn — ASCII RPG

A single-player, browser-based ASCII RPG. Next.js (App Router) + TypeScript, **client-only** (no backend; static export to `out/`), rendered with **rot.js** on a canvas, styled with **Tailwind v4**, state in **Zustand**.

## Run

- `npm run dev` — dev server
- `npm run build` — static export
- `npm run test:core` — pure-engine checks (determinism, goals, combat, connectivity, and Phase 2/3 mechanics: status effects, fire/oil, elites, stealth, ranged, altars, cracked-wall demolition, decals, shop selling, the survive siege, class active abilities, run modifiers, par-for-score bonus, a par-reachability floor, flood set-piece (altars stay reachable, doors dam the water), chasm falls (shover knockback into the void), bramble (snag-bleed + fire clears it), spore vents (bounded poison haze), lore props (placed/distinct/reachable), ambient wisps (flee/harmless/disperse), the gallery generator (niche offerings + varied collapsed pit), the dawn/dusk ambient beat (`beatAmbient` warms vs. dims by intensity), all-placed-items reachability incl. gated hut/vault loot, and that **every run modifier preserves the generator guarantees** (each trial + the all-on stack × levels × seeds: objectives reachable, no orphaned pockets, a trap-free route survives Treacherous)) via `scripts/verify-core.mts`. Tests mechanics in **isolation** (one hand-built scenario per check).
  - `[54] Color legibility` treats readability as a correctness property (it's an ASCII game — a glyph you can't pick out is a bug): the chasm's bg tint vs off-map black, status tints tellable apart, `@`/`>` popping against every terrain, floor-vs-wall separation, and a regression floor for hazards against terrain they can actually appear on. Thresholds are **measured, not guessed** (`colorDistance`, a redmean approximation in `tiles.ts`), and the scope is deliberately honest: color distance can't adjudicate every case — a trap reads fine at ~221 because its `^` carries the signal, while the old spore haze died at ~200 because a drifting mote has only color. Eyeballing is still required, which is what **`/style`** is for.
  - `[53] Load-bearing invariants` exists because a **mutation audit** (break real game code, check the suite reddens) found them uncovered: the min-1 damage floor (without it an over-armored monster is unkillable and the fight can't resolve), poison/bleed/burn actually dealing damage, and the sneak bonus beating an alerted strike.
  - `[0] Content integrity` runs FIRST by design: it sweeps every string id wiring content together (spawn/drop tables, structure + vault loot, shop tiers, monster loot, class kits, quest tags, ambient species) and every declared hex color. Those ids are invisible to the type system, and one typo otherwise surfaces as a raw stack trace from whichever later test happens to generate that level — or never, for ids generation doesn't touch (a bad `SHOP_TIERS` entry reaches the player, not the suite). Validating up front turns it into one line naming the exact offender.
  - Two harness guards keep tests from passing while verifying nothing: **`checkOver`** (use for any assertion over a runtime-built collection) FAILS on an empty set — `[].every()` is `true`, so a setup that silently produced nothing would otherwise report green; and **`levelIndexBy(label, pred)`** replaces bare `LEVELS.findIndex` for tests premised on a level existing — on a miss it exits 1 naming the lost premise instead of crashing on `LEVELS[-1]` (retiring the last `killCount` level broke two tests exactly that way).
  - Both suites are **deterministic** — byte-identical output across repeat runs, so a diff is always a real change.
- `npm run test:play` — **autonomous-playthrough / balance harness** (`scripts/verify-playthrough.mts`): a greedy bot (real class kit + the shop consumables a player buys — heals & firebombs — no god-mode) plays every level across many seeds and asserts no invariant violations during real play, navigation/attrition levels are bot-beatable, boss/siege levels are enterable (not instant wipes), and outcomes are deterministic. The bot bump-attacks, auto-heals when low, hurls firebombs at bosses/clusters (kiting to reopen bombing distance), fires an equipped bow, and **flees to open ground on survive levels / when surrounded**, so boss & siege win-rates are a real (if conservative) signal of the intended toolkit, not just pure melee.
  - Prints a per-level difficulty table (win-rate / median turns / median end-HP / median gold-earned / **medSeen** = how much of the map a winning run explored, as `share%/absolute-tiles` / median death-turn) plus a **run-level economy** summary (whole-run purse vs. the cost of buying out every shop, asserted to stay in a 15–90% band so the shop remains a real choice — neither "buy everything" nor "afford nothing"). `medSeen` is a **design** metric (content in tiles nobody walks is content nobody sees) — but compare the ABSOLUTE tile count across levels, not the share: the share is skewed by how open a map is (the Great Hall is 77% floor, so it scores a low 21% while actually being walked farther than any level but the Blackwood). Within a level, the share is the useful figure — the win-rate is a conservative **floor** (greedy, non-optimal bot), so a low win% _with_ a low death-turn flags a meat-grinder; use the table to spot over/under-tuned levels. (The final lich stays ~0% — its multi-phase barrage/summon/blink fight is beyond a greedy bot, so that row is "not measurable here," not a balance verdict.)
  - Every row plays levels in ISOLATION with a fresh, fully-stocked player, so `[P4]` adds **full-run continuity** — ONE carried character through the whole quest with real shopping and 3 lives (death restarts the level from the entry snapshot, as the store does). That's what exposes curve/economy effects the isolated table hides: `beginLevel` refills HP each level, so a carried run runs short of **consumables and gear money**, not HP — and the economy line above is an UPPER bound (it sums per-level medians as if all ten are cleared, whereas a real run banks far less). Its depth bar is a regression floor, not an ambition: the greedy bot spends its 3 lives on the first boss it can't out-trade, so ~3 levels is its natural ceiling.
  - The table is a **Warrior** sweep; `[P3]` re-runs a reduced sweep as **every class** and holds each to the same "clears every navigation/attrition level" bar — Rogue and Pyromancer carry very different kits, so without it two-thirds of the classes would only ever be unit-tested in isolation.
- `npm run test:store` — **store-level orchestration harness** (`scripts/verify-store.mts`): drives the vanilla Zustand store (`gameStore`) headlessly to assert the LoopDriver's run/screen flow — boot (splash→class→opening narration→play), the anti-skip input-settle guard, level-clear→narration→shop→next-level ordering, shop economy (buy coin/qty caps + sell), death→restart-level vs. last-life→game-over, final-level→victory, the lore-prop interaction flow (step onto → read modal → dismiss → stays read), the save/resume roundtrip,
  - **save fidelity** (a mid-run state with every recent field populated — drifting gas, lingering fire, decals, cracked-wall bash progress, known traps, quest progress, read-lore/spent-altar flags, flood step, active mutators — survives a quit→resume intact; plus a structural walker that rejects any live GameState value JSON can't carry, since a `Set`/`Map` degrades to `{}` on BOTH sides and would fool a naive equality check — this is what actually backs the docs' "JSON-safe → roundtrips in the save" claims, including for fields not yet written),
  - and **save compatibility** (a stale `contentVersion`, an unknown schema version, and corrupt/unparseable blobs each retire gracefully — Resume hidden, `resumeGame` bounces to the splash, boot never throws; this is the path every version bump relies on). Installs an in-memory `localStorage` shim (`sound`/`effectBus` self-guard to no-ops under Node).
- `npm run test:all` — runs all three suites in sequence.
- `npm run lint` / `lint:fix` — ESLint (flat config `eslint.config.mjs`: `eslint-config-next` core-web-vitals + typescript, with `eslint-config-prettier` last; React-hooks rules off for the pure `src/game/**` + `scripts/**`). `npm run format` / `format:check` — Prettier (`.prettierrc`, double quotes). A **husky pre-commit hook** (`.husky/pre-commit` → `lint-staged`) runs Prettier `--write` **then** ESLint (no `--fix`, so a lint error fails the commit) on staged files.

**Dev tooling** (gated on `DEV = process.env.NODE_ENV !== "production"`, so it's absent from the static build): the splash shows a **level picker** that jumps into any level with a tier-appropriate loadout (`store.debugJumpTo`), and in play `>` skips to the next level (`debugSkipLevel`). **`/style`** (`app/style/page.tsx` → `screens/StyleGallery.tsx`) is a dev-only **visual reference**, and the place to sanity-check anything visual. Sections: **tiles × biomes** as actually rendered; **POIs & overlays** (altar unspent/spent, lore inscription/remains/read, fire burning/guttering, gas, the barrage telegraph, `@`) — these are drawn OVER the grid and aren't `TileType`s, so they'd otherwise be invisible here; **lit vs. remembered** (fog ×`FOG_DIM`, since a color can read when lit yet vanish from memory); a **glyph-collision report** (one character meaning two things — it reads the RENDERED glyph via `terrainGlyph`, not the raw table, and labels deliberate collisions like floor/trap as intentional); biome palettes/ambients/atmospheres; monsters; class badges; items; **one monster under every tint it can wear** (species / elite / debuff); decals; weather. Everything carries a live contrast reading (red &lt;110 / amber &lt;200 / green). It owns its own scroll container because `globals.css` sets `body { overflow: hidden }` for the game. It exists because the visual bugs that shipped were only ever caught by eye, late, after playing to the level that showed them; this makes that pass instant and systematic. Test `[54]` enforces the numeric floors, the gallery covers the judgement calls it can't.

## Architecture — one-directional data flow

```
KeyboardInput → store.handleCommand → store.submitAction (the turn-based LoopDriver)
   → pure core transitions (resolveTurn) → new GameState
       ├→ React HUD/screens (Zustand selectors)
       └→ rot.js CanvasRenderer (store.subscribe)  +  cosmetic effects via effectBus
```

React and the canvas are **read-only consumers** of state. No timing lives in the core — that keeps a future turn-based→real-time swap contained (replace `submitAction`/`LoopDriver`, add tweening; core/renderer/save untouched).

### Load-bearing rules

1. **Two RNG streams** (`src/game/core/rng.ts`). Map geometry is seeded from the GLOBAL `ROT.RNG` via `seedMapGen(levelSeed(master, index))` — a pure function of seed+index. Gameplay uses a separate cloned `Rng` whose state is persisted in the save. Never let them share.
2. **Canvas is client-only.** `src/app/page.tsx` dynamically imports `GameRoot` with `ssr:false`; `ROT.Display` is created in a `useEffect` and appended to a React-owned div. React never reconciles canvas contents.
3. **Pure core.** `src/game/core/**` has no React/Zustand/DOM imports. `resolveTurn` (`src/game/core/actions/index.ts`) mutates a GameState and returns a `TurnResult` (including cosmetic `events` for the animation layer — animations NEVER touch game state).

    - **stealth-reactive "held breath"** (`setMusicExposure`, fed by `musicExposure` in `GameRoot`) — when a chaser-type threat is visible but still `idle` (you're creeping past unseen) exposure falls toward 0 and the melody + sparkle thin away to just drone + wind; the instant one enters `chase` it blooms back

    - **dawn/dusk harmonic beats** (`setMusicWarmth`, fed by `musicWarmth` mirroring the lighting beats' triggers) — +warmth blooms a bright major third+fifth over the drone, opens the timbre, adds sparkle (the Throne rekindling as Malachar falls); −warmth seeps a dissonant minor-second + darkens (the Antechamber's deepening dusk)
    - **evolving harmony** (`chordRoot`/`Track.progression`) — the low drone + danger pulse drift through a diatonic chord loop (`DEFAULT_PROGRESSION`, indexed into each track's own scale) rather than holding the tonic; one-shot **death** dirge + **victory** fanfare on those screens; short in-key **event stings** (`playSting`, layered OVER the running track — reads the current track's root/scale so they stay diatonic): a wistful fragment of the Ember motif on reading a **lore** prop, a cold unresolved tritone **shimmer** on accepting an **altar**, a brief resolving **cadence** on **level-clear** (triggered store-side in `acceptAltar` / the lore-open path / `handleLevelComplete`); runs on `sound.ts`'s shared context via a separate quieter music bus; `GameRoot` subscribes to the store and calls `playMusic`/`stopMusic` from `mode`+biome+`soundOn`, keeping one track flowing across intro→gameplay, and resumes the gesture-gated context on the first click/keypress (`resumeAudio`) so the title theme can start on the splash

## Rendering

### Viewport & camera

Camera-based viewport: the renderer draws a window sized to the host at a fixed cell size (`TARGET_ROWS`) and scrolls to keep the player in view (edge-clamped) — the map may exceed the viewport.

### Lighting

Fog-of-war with **dynamic colored lighting** (`src/render/lighting.ts` → `computeLightMap`, via `ROT.Lighting`): multi-source light spreads through the FOV and bounces off surfaces — a flickering torch pool (dims + warm-shifts + gutters as `torchFuel` runs low; a **steady** faint eyes-only ember when unlit), per-tile-flickering fire, a gold Sunblade glow, cold-violet altars, teal **glowcap fungi** (bioluminescent grotto terrain that IS a light source — a dark `cavern` region navigable by its own glow), a boss aura, a pulsing red underlight on the lich's telegraphed barrage, and transient bolt/blast/hit flashes fed from the FX layer (`fxLights`). Each visible tile's glyph color is multiplied by (**per-biome ambient** + computed light) in the single `litVis` choke point; the ambient eases from a biome center-tint at the player to a ~fog-level edge floor (so a visible tile never reads darker than explored memory — no black ring at the vision rim). `explored` = darker memory, unseen = black; a throttled ambient rAF loop (`AMBIENT_MS`) drives the flicker + recomputes the light map; visible **water shimmers** and **marsh reeds sway** on the same loop (all off under `prefers-reduced-motion`, which also freezes the light steady). All lighting tuning (ambient tints, source colors, reflectivity, passes) lives at the top of `lighting.ts`.

### Set-piece lighting beats

**Set-piece lighting beats** modulate the per-region ambient off existing triggers (all in `renderBase`, cresting with the danger-music swell). Two use `LevelConfig.lightingBeat` with a gentle pulse, but DIFFERENT triggers (the levels are shaped differently): **`"dawn"`** (Throne) is keyed to Malachar's remaining HP — his multi-phase fight IS the level, so the hall warms + brightens toward a rekindled sunrise as his HP drains, cresting on the kill (the quest's payoff); **`"dusk"`** (Antechamber) is keyed to how far the player has **advanced toward the Herald** (the gate) — `1 − dist(player,boss)/dist(entry,boss)` — NOT his HP, because the Herald dies fast and the level then transitions, so an HP-keyed dusk would bottom out for only the instant before you leave; distance-keyed, the dim/cool deepens across the whole approach and peaks as you reach him. The color transform itself is the pure, unit-tested `beatAmbient(beat, g, ambient)` in `lighting.ts` (renderBase computes the eased intensity `g` and maps it over each region's ambient). The third: the **Sunken Crypt darkens + cools** as its flood rises (`floodStep`).

### Cosmetic FX

Cosmetic FX (via `effectBus` → `CanvasRenderer.playEffects`): `projectile` (head + fading trail), `hit` (white→ember spark), `blast` (expanding ring of sparks over the firebomb/Ruin radius) are canvas-drawn on the fx rAF loop; `damage` spawns a DOM `.dmg-num` that floats up and fades (red toward the player, gold toward monsters; anchored via the canvas's `offsetLeft/Top`; skipped under reduced-motion).

### The overlay canvas

A second **transparent overlay canvas** sits exactly atop the rot.js canvas (created in the renderer's constructor, sized/positioned + scrolled in lockstep each `paintOverlay`) and carries the effects the cell grid can't: (a) additive **bloom** (`paintBloom`) — soft radial-gradient halos on the brightest sources (fire, the Sunblade, glowcap fungi, in-flight bolts) blended with `globalCompositeOperation="lighter"` so they radiate; plus **per-biome atmosphere** (`BIOME_ATMOSPHERE` in `tiles.ts` → `paintAtmosphere`): drifting mist blobs (marsh/crypt), snow (mountain), rising embers (throne), dust motes (castle), drifting glow-spores (cavern) — procedural from the clock, off under reduced-motion. A level may also set **`LevelConfig.weather`** to override its base-biome atmosphere: **`"rain"`** = gentle falling rain streaks (the cursed **Blackwood**), **`"storm"`** = heavier rain PLUS periodic **lightning** flashes (`paintLightning` — a clock-driven white flash over the visible scene, main strike + aftershock; gated on `"storm"` only) on the exposed **Ramparts**. Both map through `WEATHER_ATMOSPHERE`. Bloom + atmosphere are then clipped together to the visible FOV set (one-fill `destination-in` in `clipToVisible`) so nothing bleeds past walls or into unseen tiles; and (b) cracked-wall **knockout fissures** painted in the background color (`#0d0d0d`) that cut through the wall glyph so it reads as fractured (per-tile-deterministic shape; needed because rot.js allows only one fg color per cell). The overlay sits _above_ the glyphs (the base canvas is opaque), so light is additive rather than occluding.

### Decals

**Persistent decals** (`GameState.decals`, index → `"scorch"`|`"blood"`; scorch stamped when a fire tile burns out, blood when a monster dies via `awardKill`; capped by `CONFIG.maxDecals`) are drawn on the overlay as soft **organic blobs** (`drawDecal` — a seeded rotated/squashed radial-gradient oval + splatter droplets for blood), clipped to the visible FOV with the bloom.

### HUD overlays

HUD overlays on the map region: `BossBar` (prominent HP bar shown while a boss — `isBoss` — is in `visible`), `EliteBars` (compact top-left HP bars for tough non-boss threats in view — champion elites and `MonsterDef.miniBoss` guards like the Gate Warden; capped at 4), and `LevelIntro` (a title+goal card that fades in when a level opens, then unmounts on a timer — it remounts because the canvas region unmounts during narration/shop).

### ASCII art

ASCII art (`AsciiArt`) supports flat color, CSS `gradient`, per-row `lineColors`, or per-region inline `{key}` `colors` tokens (tokens are zero-width → alignment safe); parents use `text-center`, so `.ascii` forces `text-align:left` to keep columns.

## Game systems

Feature-complete: splash → **10** procedural levels with narration → win/lose. Grouped by area;
each entry names the symbols to start from.

### Loop, goals & pacing

- Turn-based bump combat, fog-of-war, items/inventory/equip, 3 lives, save & resume.
- **Six goal types**: reach / collect / find / kill-boss / **cull** N (`killCount` — supported but unused; the Iron Gate moved to kill-boss so its big map gets traversed) / **survive** N turns vs an **escalating siege** (`maybeReinforce` spawns growing waves from a ring around the player up to `CONFIG.siege.cap`, so you must fight/kite, not turtle).
- **Pacing:** the turn limit is a **par-for-score** target, NOT a threat. Only `survive` levels show a gauge (there the clock _is_ the goal); elsewhere there's no countdown and no overtime, and clearing under par grants an end-screen **efficiency bonus** (`levelParBonus` → `PlayerState.parBonus`). Running long costs nothing.
- **Arc:** dungeon → blackwood → mire → frostspine → **Blackhall Castle** (iron gate → great hall → sunken crypt → ramparts → dusk antechamber) → throne. Monsters toughen, light dwindles, par tightens.

### Economy & shop

- Between-level shop (5 tiers; buy + **sell** spare bag gear at `CONFIG.sellRate` × `sellPrice(def)`).
- **Deliberately lean** so the shop is a real "what can I afford?" choice and attrition can cost a life. Tune the GLOBAL dials, not per-level counts: `CONFIG.lootScale` (0.67) scales ground drops, `CONFIG.forageScale` (0.5) scales wild-heal tiles (both applied in `generate.ts`, on top of any run-modifier tweak), `CONFIG.coinPile` (3–9) sizes gold piles, monster `coinReward` values stay modest, and shop heal stacks cap at `maxQty` 2.

### Generation guarantees (load-bearing)

- **Traps are always avoidable** — never beside the start, only where a bypass exists (`openOrthoCount ≥ 3`), and `ensureTrapsAvoidable` demotes any trap bridging to an otherwise-unreachable tile, so **every walkable tile is reachable without stepping on one**.
- **No teasing dead pockets** — `sealUnreachable` flood-fills from the player (cracked walls and shut doors count as passable) and walls off anything it can't reach.
- Both run AFTER hazard/region carving, so sub-biomes and vaults can't break them.

### Terrain & hazards

- **Impassable**: `water` (Rimewalk freezes it to a permanent `ice` bridge; floods can fill it) and `chasm` (a void — only Levitation crosses, no ice bridge).
- **`oil`** slicks (`LevelConfig.oilCount`) catch fire and the blaze races one tile/turn across them, burning each to bare floor.
- **`bramble`** thickets (drawn `&` — deliberately NOT `‡`, the altar's glyph: a hazard and a boon must never share one, which `/style`'s collision report exists to catch) **snag** whoever pushes through, refreshing a short bleed (`CONFIG.brambleBleedDuration`, `brambleSnag`; entered via `movePlayer`, alongside `springTrap` for traps); Levitation floats over them. They're **flammable**, so burning a path clears the thicket (`igniteTile`/`tickFires`) — a firebomb or the Pyromancer's Scorch shines here.
- **`sporeVent`** fumaroles (`LevelConfig.sporeVentCount`; placed as isolated singletons ≥`SPORE_VENT_GAP` apart by `placeSporeVents`, so clouds never merge into one lethal fog) seep a lingering **poison haze** (`GameState.gasTiles`, JSON-safe). `tickGas` re-emits on the vent + orthogonal neighbors each turn and swells one diagonal ring every `CONFIG.gas.breathPeriod` — a bounded pulsing pocket, not a spreading tide; `CONFIG.gas.poisonDuration` sets the affliction. **Levitation gives NO protection** (it's airborne); go around or cure with an Antidote. Deterministic (no RNG).
- **`crackedWall`** (`crackedWallCount`) — placed only where it separates two open spaces (so it's a real shortcut). Opens three ways: an explosion (firebomb/Ruin), a **knockback** weapon slamming a monster through it, or melee-bashing it down over `CONFIG.crackedWallToughness` bumps (`GameState.crackedWallHits`).
- **Doors** (`door` shut = blocks move + sight; `doorOpen` = walkable + see-through; `LevelConfig.doorCount`). Generated OPEN on 1-wide chokepoints (`placeDoors`) so guarantees are unaffected. Bump to open; `[c]` (`closeDoor` action → `closePlayerDoor`) pulls one shut to break LOS, wall off pursuers, or dam a flood. Most monsters reroute (door-aware `stepToward`); `MonsterDef.opensDoors` foes (goblin, Gate Warden, Herald, Malachar) spend a turn forcing it.
- **`forage`** heal tiles (`LevelConfig.forageCount`) tucked in nooks off the beeline (`placeForage`): step on one for a little HP (floats a green `+N` via the `heal` `GameEvent`) (`forageStyle(biome)` — outdoor berries +1, arcane motes +2; generous outdoors, sparse in the castle, none in the throne), then it's spent. Skipped at full HP.
- **Knockback cuts both ways.** `ItemDef.knockback` (Flanged Mace) shoves a struck survivor back — into water/chasm is an instant kill (`isWalkable` gates the shove). `MonsterDef.knockback` foes (**Gargoyle Sentinel**) shove the PLAYER; into a chasm/water while not levitating is a **fall**, a lost life (`resolveMonsterAttack`). Telegraphed by the visible void plus a **brink warning** (`senseBrink`), and your own steps into a chasm are always refused — so it's positioning skill, never a surprise.
- **Torch fuel** — managed light; sensed traps live in `GameState.knownTraps`; a guttering torch dims and warms as it dies.

### Status effects, combat & AI

- **Status system** (`src/game/core/status.ts`, `PlayerState.effects`, ticked by `tickEffects`) — a timed-effect bag on player AND monsters: poison/bleed/burn (armor-ignoring DoT) + chill (a brief freeze; monsters skip their turn). Monsters afflict via `MonsterDef.inflicts`, the player back via weapon `ItemDef.onHit` (Frostbrand chills) and firebombs. Cured by Antidote (`cleanse`); DoT ticks route through the normal death path and float a status-tinted number.
- **Potions** — Warding (halves damage), Might (weapon boost), Vial of Ruin (self-AoE), Draught of Seeing.
- **Terrain-defying draughts** (each an `effects` key) — **Levitation** (`levitate` — glide over water/chasm, float over traps unsprung; lapsing over water scrambles you to shore via `landFromLevitation`), **Emberstep** (`emberstep` — suppresses fire searing), **Rimewalk** (`frostwalk` — freezes crossed water to permanent `ice` — enemies can use it too), **Shadowcloak** (`shadow` — caps detection at `CONFIG.shadowSightRadius`), **Phial of Blinking** (`blink`; `beginBlinkTargeting` opens the cursor, `blinkTo` → `resolvePlayerBlink`, teleport within `CONFIG.blinkRange`).
- **Fire** — firebombs thrown via the `targeting` cursor (`throwAt`) scatter lingering `GameState.fireTiles` that sear whoever stands in them and burn down over a few turns, leaving scorch decals.
- **Elites** (`MonsterInstance.elite`, table in `ELITE`; rolled per `LevelConfig.eliteChance`, never on bosses) — **brute** (tankier, hits harder), **swift** (acts twice/turn), **volatile** (bursts on death for `CONFIG.eliteExplodeDamage`). Double coins, guaranteed loot, champion tint.
- **Stealth via light** — detection is capped at `min(sightRadius, player.lightRadius, shadow ? CONFIG.shadowSightRadius : ∞)`, so dousing your torch lets you approach unseen; striking a still-`idle` chaser is a **sneak attack** (`CONFIG.sneakMultiplier`).
- **Monsters aren't omniscient** (`actMonster`) — when they lose you they hunt your **last-seen tile** (`MonsterInstance.lastSeen`) and after `CONFIG.loseInterestTurns` give up back to `idle` (`lostTurns`), so breaking LOS and waiting genuinely shakes a pursuer. Bosses never lose interest.
- **Ranged weapons** (`ItemDef.ranged = {range, ammoId}`) — with a bow equipped, bump = point-blank shot and `[f]` opens the cursor (`kind:"ranged"`) to loose at a tile in range + LOS (`shootAt`); each shot spends an `am_arrow`, and running out drops you to a feeble 1-dmg jab.
- **Monster loot** (`MonsterDef.loot` = chance + weighted table) drops on the corpse tile; bosses guaranteed.

### POIs & exploration

- **Altars** (`GameState.altars`, `LevelConfig.altarCount`, `src/game/core/altar.ts`) sit on **walkable** floor and never block a route — the offer opens AFTER you step on, so declining just walks you past. One pre-rolled bargain each (vigor: gold→+maxHP; **warblood**: −maxHP→permanent `PlayerState.weaponBonus`; hoard: HP→potions+gold); `applyAltar` is pure.
- **Lore props** (`GameState.lore`, `LevelConfig.loreCount`, text in `src/content/lore.ts`) — walkable `¶` glyphs placed by `placeLore` into NOOKS off the beeline (`openOrthoCount ≤ 2`). Step on an unread one to open a read-only `lore` mode (`LoreModal`; marks it `read` so it won’t reopen); no cost, no boon — the payoff is STORY. Each fragment is drawn from the pool of **the prop's own REGION**, not the level's base biome, so it speaks for where it lies and sub-region-only pools (`grove`/`undercity`/`cavern`/`ashen`) actually reach the player. Corollary enforced by test `[0]`: a fragment must not name a place its biome can appear OUTSIDE of. Flood levels protect lore tiles so an inscription never drowns unreadable.
- **Ambient wildlife** (`MonsterBehavior "ambient"`, placed via `LevelConfig.ambient` OUTSIDE the combat `monsterBudget`) — they **drift** and **flee** within their shy radius (`driftAmbient`), never attack, and **disperse** harmlessly when bumped (no combat, coins, loot, or kill credit). Kept rare so they read as a treat: the **Will-o'-Wisp** (`wisp`, Blackwood — also a drifting light source via the opt-in `MonsterDef.glow`), **Carrion Ravens** (`raven`, Ramparts), **Mire Frogs** (`marsh_frog`), a **Snow Hare** (`snow_hare`, Frostspine). New species are pure data — an `ambient` `MonsterDef` + a `LevelConfig.ambient` entry.

### Classes, abilities & run modifiers

- **Classes** (`src/content/classes.ts`; picked on the `classSelect` screen, stored as `PlayerState.classId`) — **Warrior** (Short Sword + Leather, 26 HP, `damageReduction` 1), **Rogue** (Dagger, 16 HP, `sneakMultiplier` 3 + `critChance` 0.2), **Pyromancer** (Bow + arrows + firebombs, `bombPower` +6). Passives read at their sites: DR through the shared `mitigate` choke point (enemy melee + bolts, not hazards), sneak/crit in `resolvePlayerAttack`, bomb bonus in `detonateAt`. `"wanderer"` is the neutral baseline for tests/legacy saves. Each has a glyph badge (`ClassDef.glyph` — ⚔ / † / ✷).
- **Active abilities** (`ClassDef.ability`, `[q]`, on `PlayerState.abilityCooldown`; routed through `useAbility`, aimed via `triggerAbility`) — Warrior **Cleave** (hits every adjacent monster), Rogue **Dash** (leap 3, landing like a blink), Pyromancer **Scorch** (a widening cone of `igniteTile`). Directional ones open a lightweight aim where the **next movement key IS the direction**.
- **Run modifiers** (`src/content/mutators.ts`) — opt-in seeded trials picked after class select (a `mutators` UI mode + `MutatorSelect` screen; `store.selectedMutators` → `beginRun`). `applyLevelMutators` runs in `beginLevel` BEFORE generation (so all generator guarantees still hold); `applyPlayerMutators` does run-start tweaks. Active ids live on `GameState.mutators`, roundtrip in the save, and raise the end score (`mutatorScoreMult`, shown on `RunStats` alongside `store.runResult`). Set: Dark Deepens / Restless Dead / Treacherous / Forsaken / Champions / Glass. The playthrough bot never selects them.

### The boss fight

Malachar (`behavior: "bossLich"`, tuned in `CONFIG.lich`) fights in three HP-gated **phases** (>2/3, >1/3, ≤1/3) that escalate ability frequency and scale: he hurls bolts, **summons** capped clusters of risen dead, rains a **telegraphed dark-fire barrage** (`GameState.barrage` marks tiles one turn, `resolveBarrage` detonates at the top of the next monster phase — one turn to step clear), and **blinks away** (`lichTeleport`) when cornered from phase 2 on.

### Sub-biome regions

`GameMap.region`/`regionBiome`/`regionPalette` tag each tile with a region id (0 = the level's own biome; JSON-safe `number[]`, so they roundtrip in the save). `carveSubBiome` shapes an optional `LevelConfig.subBiomes[]` — an ARRAY, so a level can host several regions (ids 1, 2, …) — two ways per entry:

- an organic **Simplex-noise blob** (`carveSubBiomeBlob`) — cosmetic, never touches tiles;
- a rectangular **wing whose _structure_ is a secondary generator** (`carveSubBiomeWing` + `spec.layout`, e.g. a `maze` catacomb) — bridged to the main map by cleared cross-arteries so a perfect maze stays navigable.

`scatterRegionHazards` then fills the region with a **hazard kit** (`spec.hazards[]`; omit to inherit a per-biome default from `BIOME_HAZARDS`) as scattered specks, or as flood-grown contiguous **pockets** via `clumps`. All of it runs BEFORE the connectivity pass, so the generation guarantees still hold (a severed pocket is just abandoned).

The renderer resolves biome/palette **per region** — `terrainGlyph`/`terrainColor`, the lighting ambient in `litVis`, and `paintAtmosphere` (which gates each biome's weather to its own region's cells).

**Adding a biome** is data: extend the `Biome` union, fill its tables (lighting ambient, music mood, title gradient, lore pool, and optionally atmosphere / glyphs / `BIOME_HAZARDS`), then reference it from a `subBiomes[]` entry. Sub-region-only biomes (`cavern`, `ashen`, `grove`, `undercity`) never appear as a level's base biome.

### Map generators

New `GeneratorKind`s — `rogue`, `maze` (`DividedMaze`), plus custom `hall` (a cathedral nave, `genHall`), `rampart` (a linear wall-walk, `genRampart`) and `gallery` (a processional statue gallery, `genGallery`) join `digger`/`uniform`/`cellular` behind the shared `genGrid` helper. All are whole-level-capable and usable as wing layouts.

### Secret vaults & lairs

`LevelConfig.secretVault` (`placeSecretVault`) carves a fully-walled room of loot reachable ONLY through a single **gate** — a **cracked wall** to blast/bash (default) or a shut **door** to open. Carved AFTER normal placement so it's a separate floor component (spawns never leak in), and it survives `sealUnreachable` because both gate types count as passable in that flood (`isOpenTile`).

- **Sealed means sealed to SIGHT too.** The enclosure check covers all 8 neighbors, because FOV runs at `topology: 8` — one transparent diagonal corner used to reveal the whole vault through the "sealed" wall. Guarded by test `[56]`.
- An optional **`guardian`** (a monsterId) seals a monster in with the hoard, turning free loot into a risk/reward **lair**. Placed on the far side from the gate so breaking in doesn't drop you onto it; it can't path out because the gate isn't walkable until you open it, so a `guardChase` beast just waits, dormant.

### Freestanding structures

`LevelConfig.structures[]` (`placeStructures`) is the OUTDOOR counterpart: instead of digging into existing wall, it stamps visible **wall boxes** (floor interior + one shut door + loot) onto open clearings — a hut in the woods, a shrine in a field. It's an ARRAY, so several entries read as a **hamlet** (each re-scans for its own clearing, so they never overlap).

Stamped BEFORE the component pass (door-sealed interiors drop out of `largestFloorComponent`, so nothing spawns inside), and required to sit in an all-floor footprint + 1-tile margin on the **main reachable component** — never an isolated pocket, or `sealUnreachable` would wall the loot away. Because stamping huts can flip which component is "largest" on a fragmented map, structure levels anchor player+spawns to the SAME component the huts opened onto (`floorComponentFrom`), never merely the largest. The footprint gets its own cosmetic region (timber by default, overridable per structure via `spec.palette`) so the walls read as _built_; region is purely visual — tile TYPES still drive every mechanic.

### Per-level signature beats

Every level carries one:

- **The Pit** (56×34) — a `cellular` **cavern** wing holding several glowing **fungal hollows** (`glowcap` pockets to navigate toward) + a door-gated cell.
- **The Blackwood** (84×52) — a boggy marsh patch, a bright **glade**, a thorn-choked **briar**, drifting **will-o'-wisps**, and a ruined woodcutters' **hamlet** of five varied huts with the shards scattered among them.
- **The Mire** (72×46) — water channels, dry grassy **hummocks**, a reed-thicket `maze` wing (green `♠` labyrinth), a luminous **fungal grove** (`grove` — beautiful and poisonous), poison **spore vents**, and a lone mossy **wayshrine**.
- **The Frostspine** (72×46) — a `cellular` cave network choked with **crevasses**: frozen tarns (`water`, Rimewalk bridges them) AND bottomless **chasms** (`chasm`, Levitation only) — plus two **ice grottos**, a border **watchpost**, and a sealed **beast den** (a cracked-wall vault with a dormant Hoarfrost Bear over a Frostbrand — optional, so it's a risk you choose).
- **The Iron Gate** (66×42) — a `rogue` **gatehouse** of connected guard chambers whose goal is the **Gate Warden** held at the FAR end (`killTarget` places it farthest-from-start, so you fight ACROSS the map; a cull goal used to end in the spawn corner, leaving it unseen), opening onto an **ashen wastes** region (falling grey ash, ember-glow, pooled `oil` a firebomb turns to an inferno).
- **The Great Hall** — a `hall` **cathedral**: a colonnaded central nave with flanking side-chapels, varied per seed (proportion jitter, an optional crossing transept, an occasional chapel collapsed into a `chasm`) + a door-gated **strongroom**.
- **The Sunken Crypt** (60×38) — a catacomb `maze` wing + a bioluminescent **fungal hollow** (glowcap islands that stay dry and lit as the black water rises) + the **Blackhall underworks** (`undercity` — green-stained sewer stone and flooded channels, which is _where the flood comes from_), all of it **flooding** as you hunt the Sunblade.
- **The Ramparts** (84×34) — a `rampart` **wall-walk**: an exposed battlement over a bottomless `chasm` beyond a crenellated parapet (shove the dead through the embrasures), inner **tower rooms** to fall back to, lashed by a lightning **storm** and glazed with **ice**.
- **The Antechamber** (66×40) — a `gallery` processional **statue gallery**: a wide promenade flanked by a double **colonnade** with side aisles behind the pillars (flank / break LOS), patrolled by gargoyle "**statues**" (`guardChase` — stone until you draw near). Varied per seed: **niches** are per-bay randomized (~30% solid, the rest 1–2 deep, ~40% of deep ones cracked-wall-gated with an offering cache), and ~half of seeds drop a **collapsed** section (an interior `chasm` pit with a ragged eroded outline, kept off the spine so you route around it — but a gargoyle can shove you in). Plus a door-gated **reliquary**.
- **The Throne** (44×28) — kept tight for the boss.

### Flooding set-piece

a level fills with water during play (`LevelConfig.flood` + `tickFlood`). `computeFloodPlan` marks a protected dry **spine** (shortest path start→objectives AND to every altar, dilated one tile) that never floods, so the goal — and each interactive altar — stays reachable throughout (verified even at full submersion; an unprotected altar would drown into water yet still render its `+`, stranded); everything else rises one ring every `interval` turns (from `startTurn`, capped at `maxSteps`) from **seeds spread across the whole near→far range** (count scaled to the floodable area) so the water wells up all over — including just off your route — rather than as one distant tide you never see; never floods onto an occupied tile. Water flows THROUGH an **open door** but a door pulled shut (`[c]`) **holds it back** — non-protected `doorOpen` tiles are floodable, a closed `door` is not (checked live in `tickFlood`), so shutting a door dams the flood down that corridor (player agency against getting boxed in). Water is impassable, so **Levitation** glides and **Rimewalk** freezes a path — the terrain-defying draughts become clutch. **It can never seal you in**: the dry spine only protects a player standing ON it, so before each rise `tickFlood` reserves a walkable escape route (`floodEscapeRoute`) from wherever you are back to permanently-dry ground — without it the ring floods every neighbour and maroons you on one tile, and since the turn limit is only a score target nothing ends the run (a softlock, not a hazard; skipped while levitating, guarded by test `[55]`). The flood is also tuned to be PRESENT rather than a late surprise — it starts early and spans the whole hunt, with a thinned garrison so the water is the antagonist, not the crowd. `GameState.floodable`/`floodSeeds`/`floodStep` (JSON-safe) drive + persist it. Live on the Sunken Crypt. **Set-pieces scale**: the Great Hall is a deliberately larger, airier map (grandeur, not a grind; since the turn limit is now just a par-for-score target, size no longer fights a turn-budget guard). Note `genHall` carves ~**77% floor** — by far the most open map — so a monster/item budget tuned for a normal level leaves it hollow; its counts are set against its WALKABLE area, not its dimensions (measure with the `medSeen` absolute-tile column + POIs-per-walkable-tile, never the raw share).
