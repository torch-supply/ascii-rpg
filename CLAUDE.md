# Ember of Dawn — ASCII roguelike

A single-player, browser-based ASCII roguelike RPG. Next.js (App Router) + TypeScript, **client-only** (no backend; static export to `out/`), rendered with **rot.js** on a canvas, styled with **Tailwind v4**, state in **Zustand**.

## Run
- `npm run dev` — dev server
- `npm run build` — static export
- `npm run test:core` — pure-engine checks (determinism, goals, combat, connectivity, and Phase 2/3 mechanics: status effects, fire/oil, elites, stealth, ranged, altars, cracked-wall demolition, decals, shop selling, the survive siege, and a turn-budget-vs-map-size guard) via `scripts/verify-core.mts`

**Dev tooling** (gated on `DEV = process.env.NODE_ENV !== "production"`, so it's absent from the static build): the splash shows a **level picker** that jumps into any level with a tier-appropriate loadout (`store.debugJumpTo`), and in play `>` skips to the next level (`debugSkipLevel`).

## Architecture — one-directional data flow
```
KeyboardInput → store.handleCommand → store.submitAction (the turn-based LoopDriver)
   → pure core transitions (resolveTurn) → new GameState
       ├→ React HUD/screens (Zustand selectors)
       └→ rot.js CanvasRenderer (store.subscribe)  +  cosmetic effects via effectBus
```
React and the canvas are **read-only consumers** of state. No timing lives in the core — that keeps a future turn-based→real-time swap contained (replace `submitAction`/`LoopDriver`, add tweening; core/renderer/save untouched).

### Load-bearing rules
1. **Two RNG streams** (`src/game/core/rng.ts`). Map geometry is seeded from the GLOBAL `ROT.RNG` via `seedMapGen(levelSeed(master, index))` — a pure function of seed+index. Gameplay uses a separate cloned `Rng` whose state is persisted in the save. Never let them share.
2. **Canvas is client-only.** `src/app/page.tsx` dynamically imports `GameRoot` with `ssr:false`; `ROT.Display` is created in a `useEffect` and appended to a React-owned div. React never reconciles canvas contents.
3. **Pure core.** `src/game/core/**` has no React/Zustand/DOM imports. `resolveTurn` (`src/game/core/actions/index.ts`) mutates a GameState and returns a `TurnResult` (including cosmetic `events` for the animation layer — animations NEVER touch game state).

- `src/game/input/` — `keymap.ts` (keys → `InputCommand` contract) + `KeyboardInput.ts` (the input adapter; swap this + `LoopDriver` for a real-time model). `src/game/loop/LoopDriver.ts` — the turn/real-time seam (interface).
- `src/store/gameStore.ts` — game state, UI `mode`, turn driver (`submitAction`), input routing (`handleCommand`), level transitions, shop, save/resume.
- `src/render/` — `CanvasRenderer.ts` (viewport camera + fog + animation overlay), `Display.ts`, `tiles.ts` (glyphs/colors + biome variants). `src/lib/` — `effectBus.ts` (decoupled cosmetic-effect bus), `sound.ts` (Web Audio SFX — synthesized, no asset files; cues: hit/hurt (dealing vs taking damage), pickup, coin, quaff, shoot/thud, blast, crumble, trap, step, altar, uiSelect/uiBack, boss, level-clear, death. Most fire from a turn's `GameEvent`s via `playTurnSfx` (new cosmetic events: `pickup`/`coin`/`quaff`/`shoot`/`thud`/`crumble`/`trap`/`step`); the rest are triggered store-side — `altar` in `acceptAltar`, `coin` in `buyShopEntry`, `uiSelect`/`uiBack` in `handleCommand`, `boss` via `playBossSting` (fires once when a boss first enters view, tracked per level), `death` in `handleDeath`, `levelClear` in `handleLevelComplete`. ## Rendering
Camera-based viewport: the renderer draws a window sized to the host at a fixed cell size (`TARGET_ROWS`) and scrolls to keep the player in view (edge-clamped) — the map may exceed the viewport. Fog-of-war with **distance-based lighting**: visible tiles dim by distance from the player (bright core → dim edge; entities fade less), `explored` = darker memory, unseen = black; a throttled ambient rAF loop flickers the light-edge radius; visible **water shimmers** and **marsh reeds sway** on the same loop (all off under `prefers-reduced-motion`). Cosmetic FX (via `effectBus` → `CanvasRenderer.playEffects`): `projectile` (head + fading trail), `hit` (white→ember spark), `blast` (expanding ring of sparks over the firebomb/Ruin radius) are canvas-drawn on the fx rAF loop; `damage` spawns a DOM `.dmg-num` that floats up and fades (red toward the player, gold toward monsters; anchored via the canvas's `offsetLeft/Top`; skipped under reduced-motion). A second **transparent overlay canvas** sits exactly atop the rot.js canvas (created in the renderer's constructor, sized/positioned + scrolled in lockstep each `paintOverlay`) and carries the effects the cell grid can't: (a) a **soft torch-glow** — a warm radial gradient on the player scaled to their light radius (gently flickering, off under reduced-motion) plus a smaller additive pool under each visible fire tile, blended with `globalCompositeOperation="lighter"` to soften the hard per-cell falloff; plus **per-biome atmosphere** (`BIOME_ATMOSPHERE` in `tiles.ts` → `paintAtmosphere`): drifting mist blobs (marsh/crypt), snow (mountain), rising embers (throne), dust motes (castle) — procedural from the clock, off under reduced-motion. Glow + atmosphere are then clipped together to the visible FOV set (one-fill `destination-in` in `clipToVisible`) so nothing bleeds past walls or into unseen tiles; and (b) cracked-wall **knockout fissures** painted in the background color (`#0d0d0d`) that cut through the wall glyph so it reads as fractured (per-tile-deterministic shape; needed because rot.js allows only one fg color per cell). The overlay sits *above* the glyphs (the base canvas is opaque), so light is additive rather than occluding. **Persistent decals** (`GameState.decals`, index → `"scorch"`|`"blood"`; scorch stamped when a fire tile burns out, blood when a monster dies via `awardKill`; capped by `CONFIG.maxDecals`) are drawn on the overlay as soft **organic blobs** (`drawDecal` — a seeded rotated/squashed radial-gradient oval + splatter droplets for blood), clipped to the visible FOV with the glow. HUD overlays on the map region: `BossBar` (prominent HP bar shown while a boss is in `visible`) and `LevelIntro` (a title+goal card that fades in when a level opens, then unmounts on a timer — it remounts because the canvas region unmounts during narration/shop). ASCII art (`AsciiArt`) supports flat color, CSS `gradient`, per-row `lineColors`, or per-region inline `{key}` `colors` tokens (tokens are zero-width → alignment safe); parents use `text-center`, so `.ascii` forces `text-align:left` to keep columns.

## Status
**Phase 1 + Phase 2 + much of Phase 3 complete and verified.**
- Phase 1: splash → **10** procedural levels with narration → win/lose; turn-based bump combat; fog-of-war; items/inventory/equip; six goal types (reach / collect / find / kill-boss / **cull** N monsters / **survive** N turns vs an **escalating siege** — `maybeReinforce` spawns growing waves from a ring around the player up to `CONFIG.siege.cap`, so you must actively fight/kite, not turtle); lives/HP/turn-budget; save & resume. Arc: dungeon → blackwood → mire → frostspine → **Blackhall Castle sections** (iron gate → great hall → sunken crypt → ramparts → dusk antechamber) → throne; difficulty rises across the run (turn budget shrinks, monsters toughen, light dwindles).
- Phase 2: between-level shop (5 tiers; buy + **sell** spare bag gear back at `CONFIG.sellRate` × `sellPrice(def)`); firebomb; monster AI variety (zombie slow-chase, wraith armor-pierce, guardChase mini-boss, ranged lich); non-blocking hit/projectile animations; per-biome glyph variants.
- Phase 3 (done): **hidden spike traps** with awareness (adjacency sense reveals a faint `^`; `GameState.knownTraps`; Draught of Seeing reveals all) — never spawn beside the start, and `generate.ts` guarantees a **trap-free route to every objective** (traps are optional risk/reward, never a mandatory toll) + **impassable water/chasm** terrain; **torch fuel** (managed light); **cursor firebomb targeting** (`targeting` mode + `throwAt`); **status-effect system** (`PlayerState.effects` tick each turn) with potions — Warding (halves damage), Might (weapon boost), Vial of Ruin (self-AoE), Draught of Seeing; **run stats/score** on end screens (`store.runResult`; kills/turns/gold/time carried on the player); **monster loot drops** (`MonsterDef.loot` = chance + weighted table; potions/gear on the corpse tile, bosses guaranteed); **more content** — marsh + crypt biomes, castle sections, spider/imp/ghoul/gargoyle/gate-captain/herald, mace/scale/lantern; **juice polish** — floating damage numbers, richer FX (blast rings, projectile trails, water/reed shimmer), a boss health bar, and per-level intro cards; **status effects** (`src/game/core/status.ts`) — a generalized timed-effect bag on the player AND monsters: poison/bleed/burn (armor-ignoring DoT) + chill (a brief freeze; monsters skip their turn). Monsters afflict on hit via `MonsterDef.inflicts` (spider/imp poison, wraith bleed); the player afflicts back via weapon `ItemDef.onHit` (Frostbrand chills) and firebombs (burn). Cured by the Antidote potion (`cleanse`); debuff DoT ticks route through the normal death path and float a status-tinted number. **Environmental interplay** — thrown firebombs scatter lingering `GameState.fireTiles` that sear whoever stands in them (refreshing burn) and burn down over a few turns (drawn as flickering embers; afflicted entities' glyphs take on the debuff tint); walkable **oil** slicks (`TileType "oil"`, `LevelConfig.oilCount`) catch fire and the blaze races one tile/turn across them (burning each to bare floor); **cracked walls** (`TileType "crackedWall"`, `crackedWallCount` — placed only where they separate two open spaces, so they're real shortcuts) block movement/sight like walls but can be opened three ways: an **explosion** (firebomb/Ruin) blows any in its radius to floor; a **knockback** weapon slams a monster clean through one (instant); or the player **melee-bashes** an adjacent one, which crumbles after `CONFIG.crackedWallToughness` bumps (progress tracked in `GameState.crackedWallHits`); and **knockback** weapons (`ItemDef.knockback`, e.g. Flanged Mace) shove a struck survivor back along the blow — into water/chasm is an instant kill (`isWalkable` gates the shove; `awardKill` counts it). **Elite/champion monsters** (`MonsterInstance.elite`, table in `content/monsters.ts` `ELITE`; rolled at spawn per `LevelConfig.eliteChance`, never on bosses) come in three flavors — **brute** (tankier + hits harder), **swift** (acts twice/turn), **volatile** (bursts on death for `CONFIG.eliteExplodeDamage`); they pay double coins and always drop loot, and render in a champion tint. **Stealth via light**: monster detection is capped at `min(sightRadius, player.lightRadius)` (FOV is already light-limited), so dousing/low light lets you approach unseen; striking a chaser still in its `idle` state is a **sneak attack** (`CONFIG.sneakMultiplier`). **Equipped ranged weapons** (`ItemDef.ranged = {range, ammoId}`, e.g. the Hunter's Bow + `am_arrow` ammo bundles): while a bow is equipped, attacks fire arrows — bump = point-blank shot, `f`/Fire opens the shared cursor (`TargetingData.kind: "ranged"`) to loose at a tile in range + LOS (`shootAt` action), each shot spends one arrow; out of arrows falls back to a feeble 1-dmg jab. **Altars/shrines** (`GameState.altars`, `LevelConfig.altarCount`; behavior/text in `src/game/core/altar.ts`) sit on **walkable** floor (they never block a route — the offer opens *after* you step onto an unspent one, so declining just walks you past) — landing on one opens the `altar` UI mode with a single pre-rolled bargain (vigor: gold→+maxHP; **warblood**: −maxHP→permanent `PlayerState.weaponBonus`; hoard: HP→potions+gold); `applyAltar` (pure) pays the cost + grants the boon.

**Phase 3 remaining:** in-level shopkeeper NPC (reuse Shop UI via an `onBump` handler); difficulty multiplier; a real-time mode (implement `src/game/loop/LoopDriver.ts` + an animation-gated input model).
