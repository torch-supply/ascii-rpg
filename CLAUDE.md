# Ember of Dawn — ASCII roguelike

A single-player, browser-based ASCII roguelike RPG. Next.js (App Router) + TypeScript, **client-only** (no backend; static export to `out/`), rendered with **rot.js** on a canvas, styled with **Tailwind v4**, state in **Zustand**.

## Run

- `npm run dev` — dev server
- `npm run build` — static export
- `npm run test:core` — pure-engine checks (determinism, goals, combat, connectivity, and Phase 2/3 mechanics: status effects, fire/oil, elites, stealth, ranged, altars, cracked-wall demolition, decals, shop selling, the survive siege, class active abilities, run modifiers, and a turn-budget-vs-map-size guard) via `scripts/verify-core.mts`. Tests mechanics in **isolation** (one hand-built scenario per check).
- `npm run test:play` — **autonomous-playthrough / balance harness** (`scripts/verify-playthrough.mts`): a greedy bot (real class kit + the shop consumables a player buys — heals & firebombs — no god-mode) plays every level across many seeds and asserts no invariant violations during real play, navigation/attrition levels are bot-beatable, boss/siege levels are enterable (not instant wipes), and outcomes are deterministic. The bot bump-attacks, auto-heals when low, hurls firebombs at bosses/clusters (kiting to reopen bombing distance), fires an equipped bow, and **flees to open ground on survive levels / when surrounded**, so boss & siege win-rates are a real (if conservative) signal of the intended toolkit, not just pure melee. Prints a per-level difficulty table (win-rate / median turns / median end-HP / median gold-earned / median death-turn) — the win-rate is a conservative **floor** (greedy, non-optimal bot), so a low win% _with_ a low death-turn flags a meat-grinder; use the table to spot over/under-tuned levels. (The final lich stays ~0% — its multi-phase barrage/summon/blink fight is beyond a greedy bot, so that row is "not measurable here," not a balance verdict.)
- `npm run test:store` — **store-level orchestration harness** (`scripts/verify-store.mts`): drives the vanilla Zustand store (`gameStore`) headlessly to assert the LoopDriver's run/screen flow — boot (splash→class→opening narration→play), the anti-skip input-settle guard, level-clear→narration→shop→next-level ordering, shop economy (buy coin/qty caps + sell), death→restart-level vs. last-life→game-over, final-level→victory, and the save/resume roundtrip. Installs an in-memory `localStorage` shim (`sound`/`effectBus` self-guard to no-ops under Node).
- `npm run test:all` — runs all three suites in sequence.

**Dev tooling** (gated on `DEV = process.env.NODE_ENV !== "production"`, so it's absent from the static build): the splash shows a **level picker** that jumps into any level with a tier-appropriate loadout (`store.debugJumpTo`), and in play `>` skips to the next level (`debugSkipLevel`).

## Architecture — one-directional data flow

```
KeyboardInput → store.handleCommand → store.submitAction (the turn-based LoopDriver)
   → pure core transitions (resolveTurn) → new GameState
       ├→ React HUD/screens (Zustand selectors)
       └→ rot.js CanvasRenderer (store.subscribe)  +  cosmetic effects via effectBus
```

React and the canvas are **read-only consumers** of state. No timing lives in the core — that keeps a future turn-based→real-time swap contained (replace `submitAction`/`LoopDriver`, add tweening; core/renderer/save untouched).

### Load-bearing rules

1. **Two RNG streams** (`src/game/core/rng.ts`). Map geometry is seeded from the GLOBAL `ROT.RNG` via `seedMapGen(levelSeed(master, index))` — a pure function of seed+index. Gameplay uses a separate cloned `Rng` whose state is persisted in the save. Never let them share.
2. **Canvas is client-only.** `src/app/page.tsx` dynamically imports `GameRoot` with `ssr:false`; `ROT.Display` is created in a `useEffect` and appended to a React-owned div. React never reconciles canvas contents.
3. **Pure core.** `src/game/core/**` has no React/Zustand/DOM imports. `resolveTurn` (`src/game/core/actions/index.ts`) mutates a GameState and returns a `TurnResult` (including cosmetic `events` for the animation layer — animations NEVER touch game state).

## Rendering

Camera-based viewport: the renderer draws a window sized to the host at a fixed cell size (`TARGET_ROWS`) and scrolls to keep the player in view (edge-clamped) — the map may exceed the viewport. Fog-of-war with **dynamic colored lighting** (`src/render/lighting.ts` → `computeLightMap`, via `ROT.Lighting`): multi-source light spreads through the FOV and bounces off surfaces — a flickering torch pool (dims + warm-shifts + gutters as `torchFuel` runs low; a **steady** faint eyes-only ember when unlit), per-tile-flickering fire, a gold Sunblade glow, cold-violet altars, a boss aura, a pulsing red underlight on the lich's telegraphed barrage, and transient bolt/blast/hit flashes fed from the FX layer (`fxLights`). Each visible tile's glyph color is multiplied by (**per-biome ambient** + computed light) in the single `litVis` choke point; the ambient eases from a biome center-tint at the player to a ~fog-level edge floor (so a visible tile never reads darker than explored memory — no black ring at the vision rim). `explored` = darker memory, unseen = black; a throttled ambient rAF loop (`AMBIENT_MS`) drives the flicker + recomputes the light map; visible **water shimmers** and **marsh reeds sway** on the same loop (all off under `prefers-reduced-motion`, which also freezes the light steady). All lighting tuning (ambient tints, source colors, reflectivity, passes) lives at the top of `lighting.ts`. Two **set-piece lighting beats** modulate the per-region ambient off existing triggers: the **Throne flares** (brightens + warms in a pulse) in the lich's final phase (≤⅓ HP), and the **Sunken Crypt darkens + cools** as its flood rises (`floodStep`) — both in `renderBase`, cresting with the danger-music swell. Cosmetic FX (via `effectBus` → `CanvasRenderer.playEffects`): `projectile` (head + fading trail), `hit` (white→ember spark), `blast` (expanding ring of sparks over the firebomb/Ruin radius) are canvas-drawn on the fx rAF loop; `damage` spawns a DOM `.dmg-num` that floats up and fades (red toward the player, gold toward monsters; anchored via the canvas's `offsetLeft/Top`; skipped under reduced-motion). A second **transparent overlay canvas** sits exactly atop the rot.js canvas (created in the renderer's constructor, sized/positioned + scrolled in lockstep each `paintOverlay`) and carries the effects the cell grid can't: (a) additive **bloom** (`paintBloom`) — soft radial-gradient halos on the brightest sources (fire, the Sunblade, in-flight bolts) blended with `globalCompositeOperation="lighter"` so they radiate; plus **per-biome atmosphere** (`BIOME_ATMOSPHERE` in `tiles.ts` → `paintAtmosphere`): drifting mist blobs (marsh/crypt), snow (mountain), rising embers (throne), dust motes (castle) — procedural from the clock, off under reduced-motion. Bloom + atmosphere are then clipped together to the visible FOV set (one-fill `destination-in` in `clipToVisible`) so nothing bleeds past walls or into unseen tiles; and (b) cracked-wall **knockout fissures** painted in the background color (`#0d0d0d`) that cut through the wall glyph so it reads as fractured (per-tile-deterministic shape; needed because rot.js allows only one fg color per cell). The overlay sits _above_ the glyphs (the base canvas is opaque), so light is additive rather than occluding. **Persistent decals** (`GameState.decals`, index → `"scorch"`|`"blood"`; scorch stamped when a fire tile burns out, blood when a monster dies via `awardKill`; capped by `CONFIG.maxDecals`) are drawn on the overlay as soft **organic blobs** (`drawDecal` — a seeded rotated/squashed radial-gradient oval + splatter droplets for blood), clipped to the visible FOV with the bloom. HUD overlays on the map region: `BossBar` (prominent HP bar shown while a boss — `isBoss` — is in `visible`), `EliteBars` (compact top-left HP bars for tough non-boss threats in view — champion elites and `MonsterDef.miniBoss` guards like the Gate Warden; capped at 4), and `LevelIntro` (a title+goal card that fades in when a level opens, then unmounts on a timer — it remounts because the canvas region unmounts during narration/shop). ASCII art (`AsciiArt`) supports flat color, CSS `gradient`, per-row `lineColors`, or per-region inline `{key}` `colors` tokens (tokens are zero-width → alignment safe); parents use `text-center`, so `.ascii` forces `text-align:left` to keep columns.

The barrage telegraph renders as a pulsing danger cell in `CanvasRenderer`. **Character classes** (`src/content/classes.ts`) — New Game opens a `classSelect` screen (1/2/3 or click; Esc backs to the splash) to pick **Warrior** (Short Sword + Leather, 26 HP, `damageReduction` 1), **Rogue** (Dagger, 16 HP, `sneakMultiplier` 3 + `critChance` 0.2), or **Pyromancer** (Bow + arrows + firebombs, `bombPower` +6). `createPlayer(classId)` applies the kit + `PlayerState.classId`; passives are read at their sites — DR via the shared `mitigate` choke point in `combat.ts` (enemy melee + bolts, not hazards), sneak/crit in `resolvePlayerAttack`, bomb bonus in `detonateAt`. The neutral `"wanderer"` class (not in the picker) is the plain baseline for `createPlayer()` with no arg. Each class carries an icon (`ClassDef.glyph` — Warrior ⚔ / Rogue † / Pyromancer ✷) shown on the picker card and as a colored badge in the HUD header. **Class active abilities** (`ClassDef.ability`, bound to `[q]`, on a turn cooldown — `PlayerState.abilityCooldown`, ticked in `resolveTurn` except the use-turn): Warrior **Cleave** (`aim:"none"` — one sweep hits every adjacent monster via `resolvePlayerAttack`), Rogue **Dash** (`aim:"dir"` — leap up to 3 tiles, landing fully like a blink), Pyromancer **Scorch** (`aim:"dir"` — a widening cone of `igniteTile` fire). The `{type:"ability", dx?, dy?}` action routes through `useAbility`; directional ones open a lightweight aim (`triggerAbility` → `targeting` cursor `kind:"ability"`, and the **next movement key IS the direction** — no tile confirm), rendered as cardinal arrows around the `@` (not the firebomb reticle). Surfaced in the HUD loadout row + Help; effect balance lives in the ability functions / `classes.ts`. **Run modifiers** (`src/content/mutators.ts`) — opt-in, seeded "trials" chosen after class select (a `mutators` UI mode + `MutatorSelect` toggle-any screen; `store.selectedMutators` → `beginRun`) that reshape the WHOLE run. Each is a pure transform: `applyLevelMutators(config, ids)` runs in `beginLevel` **before** generation (light/spawns/traps/turn-budget/elites — so all generator guarantees still hold), and `applyPlayerMutators` does one-time run-start tweaks (Glass → 1 life). The active ids live on `GameState.mutators` (threaded through every level transition, roundtrips in the save) and raise the end-of-run **score** (`mutatorScoreMult`, shown on `RunStats`); a `⚠ N` HUD badge lists them. Current set: The Dark Deepens / Restless Dead / Treacherous / Hunted / Champions / Glass. The playthrough bot never selects them, so the balance table reflects unmodified runs.

**Sub-biome regions & secret vaults** — `GameMap.region`/`regionBiome`/`regionPalette` tag tiles with a region id (0 = the level's own biome; JSON-safe `number[]` so they roundtrip in the save). `generate.ts` `carveSubBiome` shapes an optional `LevelConfig.subBiome` two ways: an organic **Simplex-noise blob** (`carveSubBiomeBlob` — cosmetic, never touches tiles) or a rectangular **wing whose _structure_ is a secondary generator** (`carveSubBiomeWing` + `spec.layout`, e.g. a `maze` catacomb — bridged to the main map by cleared cross-arteries so the perfect maze stays navigable). `scatterRegionHazards` fills the region with a **hazard kit** (`spec.hazards[]` — a bog's `water` pools, a scorched hollow's `oil`, …; omit to inherit a per-biome default from `BIOME_HAZARDS`) as blobs — all carved **before** the connectivity pass, so `largestFloorComponent`/`sealUnreachable`/`ensureTrapsAvoidable` guarantees still hold (a severed pocket is just abandoned). Two new `GeneratorKind`s — `rogue` + `maze` (`DividedMaze`) — join `digger`/`uniform`/`cellular` via the shared `genGrid` helper and are whole-level-capable too. **Secret vaults** (`LevelConfig.secretVault`, `placeSecretVault`) carve a fully-walled room reachable ONLY through a single **cracked wall**, loot inside — it survives `sealUnreachable` (cracked walls count as passable in that flood) but stays physically gated until you blast/bash in, and it's a separate floor component so normal spawns never leak in. The renderer resolves each tile's biome/palette **per region** — `terrainGlyph`/`terrainColor`, the lighting ambient in `litVis`, and `paintAtmosphere` (which gates each biome's weather to its own region's cells, scattering a sub-region's particles across just that patch). Currently: the **Blackwood** carries a boggy marsh sub-biome (water pools) + a hidden cache; the **Iron Gate** an oil **scorched hollow** (an Emberstep region); the **Sunken Crypt** a catacomb `maze` wing that **floods** as you hunt the Sunblade (below).

**Flooding set-piece** (`LevelConfig.flood` + `tickFlood`) — a level fills with water during play. `computeFloodPlan` marks a protected dry **spine** (shortest path start→objectives, dilated one tile) that never floods, so the goal stays reachable throughout (verified even at full submersion); everything else rises one ring every `interval` turns (from `startTurn`, capped at `maxSteps`) from far-corner seeds, never onto an occupied tile. Water is impassable, so **Levitation** glides and **Rimewalk** freezes a path — the terrain-defying draughts become clutch. `GameState.floodable`/`floodSeeds`/`floodStep` (JSON-safe) drive + persist it. Live on the Sunken Crypt. **Set-pieces scale**: the Great Hall is a deliberately larger, _sparse_ map (grandeur, not a grind — density tuned down, `turnLimit` up to clear the test-[26] guard).

**Phase 3 remaining:** in-level shopkeeper NPC (reuse Shop UI via an `onBump` handler); difficulty multiplier; a real-time mode (implement `src/game/loop/LoopDriver.ts` + an animation-gated input model). ## Workflow notes

- Do NOT auto-commit; the user commits. Verify with `tsc`/`build`/`test:core` and leave changes for the user to review on their own dev server (don't launch `npm run dev`).
