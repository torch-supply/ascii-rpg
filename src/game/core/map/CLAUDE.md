# Map generation — notes

Detail for `src/game/core/map/**` (`generate.ts` and its helpers). The root `CLAUDE.md` owns the two-RNG-streams rule — generation draws ONLY from the global `ROT.RNG` seeded by `seedMapGen` — and `scripts/CLAUDE.md` the soak's rationale. Every guarantee below is pinned by the soak (`npm run test:soak`); run it after any change here.

## Generation guarantees (load-bearing)

- **Traps are always avoidable** — never beside the start, only where a bypass exists (`openOrthoCount ≥ 3`), and `ensureTrapsAvoidable` demotes any trap bridging to an otherwise-unreachable tile, so **every walkable tile is reachable without stepping on one** — including tiles behind a gate: the pass floods THROUGH shut doors and cracked walls (`throughGates`), since the player can open them; flooding on foot only, it never saw a hut or niche whose only approach was a trap (soak check `9`).
- **Every structural wing is GUARANTEED to connect** (`connectWing`, run after all wings are carved). A wing is a rectangle joined to the map by an artery, and that artery is fragile three ways: it's drawn BEFORE the wing's own hazards scatter, so a water clump can cut it; on an organic base it can dead-end in a one-tile pocket; and every wing used to stamp the same rectangle (right edge, vertically centred), so a second wing destroyed the first — the Mire's temple landed directly on its reed maze. In each case `sealUnreachable` then walls the wing away and the region stays TAGGED with no walkable tile, so the level silently loses a third of its content. `connectWing` checks whether the wing touches the largest floor mass and digs an L-corridor if it doesn't; wings are also anchored by ORDINAL now (right / left / top / bottom), with ordinal 0 keeping the original anchor so single-wing levels generate unchanged. Soak check `7` pins it, and it reddens hard without the fix: 33/60 seeds on the Mire, 9/60 on the Iron Gate.
  - **"Joined" means the wing's BULK, not one of its tiles — and getting that wrong is invisible by construction.** `connectWing` returned as soon as ANY region-tagged floor tile touched the main mass. A room-based layout (`hall`, `rogue`) leaves margin tiles between its outer wall and the wing rectangle, and those are region-tagged floor too, so a single margin sliver short-circuited the whole function while the hall's interior stayed marooned. It is the same error as an artery stopping at the first floor tile it meets, one level up: the wing WAS joined, just not the part anybody walks in. It now floods the wing's own floor into components, takes the largest, and tests and digs from THAT.
  - Measured on the Mire's temple (`sanctum`/`hall` — the level's destination, pinned by `goalHere`): **6.5% of seeds kept 1-2 walkable tiles out of a typical ~290**, and its reed maze another 12.5%; the Sunken Crypt's catacomb 3%. After: 0% on all six wings, with the Mire's temple p10 rising 51 → 237 tiles and the reed maze 16 → 163.
  - **Why nothing caught it, and the lesson for any future region check:** `sealUnreachable` turns the marooned floor into WALL, so after generation there is no unreachable floor left to find — only a wing that looks small. Both existing tests (`floor === 0`, `reachable === 0`) therefore passed on a wing reduced to a sliver. The detectable signal is floor measured against the region's own TAGGED footprint, which survives the walling: healthy wings bottom out at 11% (the Mire's eroded reed maze), the bug read 0.1-0.3%, and soak check `7` now fails under 5%. Reverting the fix reddens 27/200 Mire seeds and 6/200 Crypt seeds.
  - **The visible symptom was somewhere else entirely**, which is worth remembering: it surfaced as a _weird exit placement_. `goalHere` pins the exit inside the region, so when the region was a sliver the exit had nowhere to go but the one surviving cell — a one-tile hole punched through a wall with open water behind it, on 22% of Mire seeds.
- **Measure a wing by REGION ID, never by biome.** This is how the bug hid for so long. A wing whose biome equals its level's base — the reed maze in a marsh, the crypt maze in a crypt — counts base tiles when measured by biome and reads as a flawless 100%. Measured honestly, the Mire's maze was severed on **40%** of seeds and the Crypt's on 12%, long before any recent work. I drew the wrong conclusion twice from the biome-based number ("existing wings are fine, so this isn't a general bug") before noticing.
- **A wing's bridge must reach REAL space, not the first floor tile it meets.** `carveSubBiomeWing` tunnels an artery leftward out of the wing and stops when it hits floor. Stopping at the _first_ floor tile is wrong on an organic base: a `cellular` marsh is full of one-tile pockets, so the artery joined the wing to a dead pocket and `sealUnreachable` then walled BOTH away — the region stayed tagged but had zero walkable tiles. Measured on the Mire's temple wing: **severed on 35% of seeds**. It stayed hidden for so long because every wing before it used `maze` or `cellular`, which fill their rectangle densely and overlap real floor by luck; the failure only appears with a room-based layout (`hall`, `rogue`) that leaves wall margins. The stop condition now also requires an open neighbourhood, which a pocket fails and a cavern passes immediately — verified the existing wings are bit-identical (Pit 100%, reed maze 100%, crypt maze 100%). **A severed wing is invisible without a check**: nothing in the suites looked at whether a region still had floor, so the level simply lost a third of its content on those seeds and nobody would have known.
- **No teasing dead pockets** — `sealUnreachable` flood-fills from the player (cracked walls and shut doors count as passable) and walls off anything it can't reach.
- Both run AFTER hazard/region carving, so sub-biomes and vaults can't break them.

## Sub-biome regions

`GameMap.region`/`regionBiome`/`regionPalette` tag each tile with a region id (0 = the level's own biome; JSON-safe `number[]`, so they roundtrip in the save). `carveSubBiome` shapes an optional `LevelConfig.subBiomes[]` — an ARRAY, so a level can host several regions (ids 1, 2, …) — two ways per entry:

- an organic **Simplex-noise blob** (`carveSubBiomeBlob`) — cosmetic, never touches tiles, and claims only UNCLAIMED ground: built structure wins over an organic patch whatever order the specs are listed in (a blob listed after a wing used to paint over it — the Iron Gate's ashen wastes into its gatehouse on 62% of seeds; soak check `8`);
- a rectangular **wing whose _structure_ is a secondary generator** (`carveSubBiomeWing` + `spec.layout`, e.g. a `maze` catacomb) — bridged to the main map by cleared cross-arteries so a perfect maze stays navigable.

**A NATURAL wing must look grown, not built** (`SubBiomeSpec.organic`, `organicGrid`). `genGrid("maze")` is a perfect rectilinear lattice — correct for the Sunken Crypt's bone catacombs, which are masonry, and wrong for the Mire's reed thicket, where the same generator put a hedge maze in a bog. That made the level's one NATURAL feature the only thing on it generated as architecture, beside a temple and four wayshrines whose straight walls are deliberate — which is exactly what reads as "sometimes organic, sometimes not." It is **opt-in**, because rectilinear is the point for every other wing (all six structural wings: `cellular` cavern, two `maze`, `hall`, two `rogue` — and the reed maze was the only natural one). Two operations, and it needs BOTH:

- the lattice is cut at **half resolution and doubled**, which is what kills the uniform one-tile pitch. Erosion alone cannot: thinning a 1-thick wall only makes it gappy, so the lattice survives as a dotted lattice. Doubling also makes the erosion **safe** — channels are 2 tiles wide, so removing wall can never sever one and the pass stays monotone (floor only grows), so no connectivity guarantee can break.
- the walls are then **eroded** — any nub with 3+ open neighbours goes (this removes the right angles and rounds the wing's own rectangular outline into the base biome), plus **two octaves** of noise punch wandering channels. The fine octave is not decoration: doubling makes each row an exact copy of its pair, and one low-frequency field barely changes over two tiles, so the pair erodes identically and the result carries visible 2-row banding — trading the old lattice for a subtler one.

Measured on the reed wing: wall share 78% → 57%, pure-straight wall tiles 34 → 7 per seed, median straight run 9 → 7, and the level's walkable area moves only +3% so no rebalancing follows. **The erosion threshold is a look dial with a floor and a ceiling**: at 0.30 the thicket thins to 47% wall and stops being something to get lost in; at 0.52 it fills to 66% and becomes a solid blob with no channels. Test `[67]` pins both ends of the rule — the reeds must read grown AND the catacombs must stay masonry — via the share of a region's wall tiles that are pure-straight interior (catacomb 47%, reeds 6%). That metric is deliberately **not** a run-length or right-angle count: both invert at high density, since a thick bank has perpendicular neighbours and so scores as "not straight" for the wrong reason. `organic` also **throws on a room-based layout** rather than crashing inside rot.js — `ROT.Map.Rogue` dies in `_createCorridors` when asked for a half-resolution grid.

`scatterRegionHazards` then fills the region with a **hazard kit** (`spec.hazards[]`; omit to inherit a per-biome default from `BIOME_HAZARDS`) as scattered specks, or as flood-grown contiguous **pockets** via `clumps`. All of it runs BEFORE the connectivity pass, so the generation guarantees still hold (a severed pocket is just abandoned).

The renderer resolves biome/palette **per region** — `terrainGlyph`/`terrainColor`, the lighting ambient in `litVis`, and `paintAtmosphere` (which gates each biome's weather to its own region's cells).

**Two placement options make a level a JOURNEY rather than a field with an exit somewhere in it** — both narrative, not difficulty:

- `SubBiomeSpec.noStart` — a region you may never begin in. Narrative, not difficulty: several levels are a journey INTO somewhere, and spawning past the threshold spends the arc before it starts. Marked per region for the level's **destination** (the Mire's temple), a **discovery** it exists to reveal (the Great Hall's undercroft — first sight of what Blackhall keeps underground), a **labyrinth** that is somewhere you go into rather than wake in (the Mire's reeds, the crypt's catacombs), a **self-lit lure** meant to draw you from outside (the Pit's glowcap hollows, the Mire's grove), or simply hostile ground (the Blackwood's briar, whose thorns snag on entry). Still deliberately a blocklist rather than "start in region 0" — the Iron Gate reads correctly on the graves OR out on the burned siege ground, the Blackwood in woods, bog or glade — so what stays allowed is as considered as what doesn't.
  - **It is matched by REGION ID, and the biome-keyed version it replaced could not express the cases that mattered most.** A sub-region often shares its level's base biome: the Mire's reed maze is `marsh`, the Sunken Crypt's catacomb is `crypt`, and the Blackwood's glade and briar are BOTH `forest`. Blocking by biome would have taken the base region with it, or been unable to tell two sub-regions apart — the same biome-vs-region-id trap that hid the severed-wing bug. Measured across all ten levels: the Sunken Crypt began in its base region on only **40%** of seeds (27% deep in the catacombs, 25% in the flooded underworks the level's own water comes from), the Pit **50%** (the glowcap cavern is self-lit, inverting the lesson level 1 exists to teach), the Great Hall **75%**. All three now read 100%; the Iron Gate, Blackwood, Mire, Frostspine and Ramparts keep their deliberate alternates.
- **The exit is chosen for SHAPE as well as distance** (`farthestSafeCell`). It sorted purely by distance and returned the first cell whose removal gated nothing — and a one-tile hole in a wall with water behind it scores perfectly on both: it is genuinely at the region's extremity, and nothing is behind it to gate. `farthestCell` had long since learned this for quest items ("a destination, not a cul-de-sac": take everything within `FAR_SLACK` of the maximum, prefer the most open); the exit never got it. It now walks the same far-end band preferring ≥3 open orthogonal neighbours, then ≥2, then falls back to the old rule so a cramped region still gets an exit. Independently worth it: with the `connectWing` fix alone the Mire still wedged the exit on 13% of seeds and the Pit on 7%; with both, 0% and 2%.

- **A destination region can be carved next to the start** (`CONFIG.minStartToExit`, applied at the single `pushStartAwayFrom` choke point). `goalHere` takes the farthest cell WITHIN a region, which is only far if the region is — so ~2% of Mire seeds put the exit within 20 steps and the worst put it at 3. Corrected by moving the START, not the goal: the goal stays inside the region that makes it the destination, and the start is re-drawn from the same pool, so `noStart` and the component anchor still hold. A random eligible cell, not the farthest — on a triggering seed the farthest is always the opposite corner, which swaps a rare short run for a predictable one. The floor only touches the tail: the Mire's median run length is unchanged (~71) while the minimum goes 3 → 21 over 1000 seeds. **The 20-tile floor this level was once documented as already having was never true** — it was measured on too few seeds to see the tail, the same granularity lesson as the 12-seed win rates.
- `SubBiomeSpec.goalHere` — the region the level's OBJECTIVE belongs in, so it becomes the destination instead of a side room you may never enter. Covers all three single-objective goals (the `reachLocation` exit, the `killTarget` boss, the `findItem` item), because the failure is the same in each: the Gate Warden — whose entire identity is holding the gatehouse — stood out on the open graves on **60%** of seeds, wasting the one built interior on the level. Region-id keyed, replacing the biome-keyed `exitInBiome` for the same reason `noStart` is: a biome-keyed flag cannot name one of two regions sharing a biome, and silently means "any of them".
  - **Constraining WHERE the goal sits loosens how FAR it is** — necessarily, since the far end of one region is nearer than the far end of the map. Pinning the Warden inside the gatehouse took the Iron Gate's shortest run from 43 steps to **17**. `CONFIG.minStartToExit` now applies to every single-objective goal, not just the exit, via one `pushStartAwayFrom` choke point — and it is measured on a DEEPER sweep (150 seeds on each level that constrains its goal), because the 40-seed sweep caught none of that tail.
- **The APPROACH is a third distance, and it is the one an outside→inside level is actually about** (`CONFIG.minStartToGoalRegion`, 18). `minStartToExit` measures the goal TILE and can be satisfied entirely indoors: you may begin 30 steps from the Gate Warden but **three steps from the gatehouse door**, walk in, and cross the interior — skipping the outdoor half the level exists for. Measured before the floor: **13% of Iron Gate seeds put the building within 10 steps** (19% within 15), 9%/19% on the Mire, against a median approach of 35. Enforced by FILTERING the start pool rather than moving the start afterwards — the region is already carved when the start is picked, so one multi-source BFS out from it gives the true walking distance. After: minimum approach 18 on both, zero seeds under 15, and the median rose (35→40, 36→42) because the pool now favours farther starts.
- **Used together they need care, and they usually SHOULD be used together.** Both ends of a journey in one region is the worst version of this: the Mire's temple spawn meant starting essentially at the exit. The Iron Gate is the same shape read forwards — `goalHere` puts the Warden in the gatehouse, `noStart` keeps you outside the walls, and together they make the level "fight your way in". Whenever you set one, ask immediately about the other. Measured after: goal in the intended region 100%, never starting in it, min run 33 / median 76 (Iron Gate) and 30 / 69 (Mire).

**Adding a biome** is data: extend the `Biome` union, fill its tables (lighting ambient, music mood, title gradient, lore pool, and optionally atmosphere / glyphs / `BIOME_HAZARDS`), then reference it from a `subBiomes[]` entry. Sub-region-only biomes (`cavern`, `ashen`, `grove`, `undercity`, `sanctum`) never appear as a level's base biome; `graveyard` does (the Iron Gate).

## Secret vaults & lairs

`LevelConfig.secretVault` (`placeSecretVault`) carves a fully-walled room of loot reachable ONLY through a single **gate** — a **cracked wall** to blast/bash (default) or a shut **door** to open. Carved AFTER normal placement so it's a separate floor component (spawns never leak in), and it survives `sealUnreachable` because both gate types count as passable in that flood (`isOpenTile`).

- **Sealed means sealed to SIGHT too.** The enclosure check covers all 8 neighbors, because FOV runs at `topology: 8` — one transparent diagonal corner used to reveal the whole vault through the "sealed" wall. Guarded by test `[56]`.
- **The anchor (the tile you stand on to open the gate) must still be plain floor** when the vault is carved — it is the only way in, and `floors` predates the exit and traps, so a vault once anchored on the exit was unreachable (stepping there ends the level). Soak check `9` asserts every gate has an approach that is neither the exit nor a trap.
- An optional **`guardian`** (a monsterId) seals a monster in with the hoard, turning free loot into a risk/reward **lair**. Placed on the far side from the gate so breaking in doesn't drop you onto it, and off the loot (soak check `11` — the Frostspine's bear stood on the gold on every seed); it can't path out because the gate isn't walkable until you open it, so a `guardChase` beast just waits, dormant.

## Freestanding structures

`LevelConfig.structures[]` (`placeStructures`) is the OUTDOOR counterpart: instead of digging into existing wall, it stamps visible **wall boxes** (floor interior + one shut door + loot) onto open clearings — a hut in the woods, a shrine in a field. It's an ARRAY, so several entries read as a **hamlet** (each re-scans for its own clearing, so they never overlap).

Stamped BEFORE the component pass (door-sealed interiors drop out of `largestFloorComponent`, so nothing spawns inside), and required to sit in an all-floor footprint + 1-tile margin on the **main reachable component** — never an isolated pocket, or `sealUnreachable` would wall the loot away. Because stamping huts can flip which component is "largest" on a fragmented map, structure levels anchor player+spawns to the SAME component the huts opened onto (`floorComponentFrom`), never merely the largest. The footprint gets its own cosmetic region (timber by default, overridable per structure via `spec.palette`) so the walls read as _built_; region is purely visual — tile TYPES still drive every mechanic.

## Flooding set-piece

a level fills with water during play (`LevelConfig.flood` + `tickFlood`). `computeFloodPlan` marks a protected dry **spine** (shortest path start→objectives AND to every altar, dilated one tile) that never floods, so the goal — and each interactive altar — stays reachable throughout (verified even at full submersion; an unprotected altar would drown into water yet still render its `+`, stranded); everything else rises one ring every `interval` turns (from `startTurn`, capped at `maxSteps`) from **seeds spread across the whole near→far range** (count scaled to the floodable area) so the water wells up all over — including just off your route — rather than as one distant tide you never see; never floods onto an occupied tile. Water flows THROUGH an **open door** but a door pulled shut (`[c]`) **holds it back** — non-protected `doorOpen` tiles are floodable, a closed `door` is not (checked live in `tickFlood`), so shutting a door dams the flood down that corridor (player agency against getting boxed in). Water is impassable, so **Levitation** glides and **Rimewalk** freezes a path — the terrain-defying draughts become clutch. **It can never seal you in**: the dry spine only protects a player standing ON it, so before each rise `tickFlood` reserves a walkable escape route (`floodEscapeRoute`) from wherever you are back to permanently-dry ground — without it the ring floods every neighbor and maroons you on one tile, and since the turn limit is only a score target nothing ends the run (a softlock, not a hazard; skipped while levitating, guarded by test `[55]`). The flood is also tuned to be PRESENT rather than a late surprise — it starts early and spans the whole hunt, with a thinned garrison so the water is the antagonist, not the crowd. `GameState.floodable`/`floodSeeds`/`floodStep` (JSON-safe) drive + persist it. Live on the Sunken Crypt. **Set-pieces scale**: the Great Hall is a deliberately larger, airier map (grandeur, not a grind; since the turn limit is now just a par-for-score target, size no longer fights a turn-budget guard). Note `genHall` used to carve ~**77% floor** — by far the most open map, so a monster/item budget tuned for a normal level left it hollow. Its chapels are now real rooms cut into rock (**42%**), but the rule that produced that bug still holds: a `hall` level's counts are set against its WALKABLE area, not its dimensions (measure with the `medSeen` absolute-tile column + POIs-per-walkable-tile, never the raw share), and changing the generator's floor share is a change to density that the population has to follow.
